Driving History Check (DL06)

1. Overview

The Driving History Check (transaction DL06, program DLISHIST) is a CICS pseudo-conversational COBOL application. It is one step in the driver’s licence application workflow. A licensing officer enters an application ID and sees the applicant’s name, licence type and active driving incidents on a 3270 screen. The incidents are shown as a scrollable list. The officer can then run a formal history check, which decides whether the applicant passes.

The application does the following:

  • Looks up the application. It reads the licence application and the candidate who owns it, using the application ID.
  • Loads the driving history. It retrieves the candidate’s active incidents (RECORD_STATUS = 'A'), newest first. It keeps up to 50 of them for display and works out summary indicators.
  • Shows the history. It displays seven incidents at a time, with F7 and F8 scrolling.
  • Applies the pass/fail rules. The check fails for any of these reasons:
    • An active suspension or disqualification.
    • More than 12 total demerit points.
    • Unpaid fines.
  • Is gated by eligibility. The check runs only if the earlier eligibility check has passed (ELIG_CHECK_STATUS = 'P').
  • Records the outcome. It writes the result, reason and new application status to DLIS.LICENSE_APPLICATION.

1.1 Function Keys

Key Action
F1 Run the history check, which evaluates the rules and updates the application
F3 Load the application, then show the candidate and history (no database update)
F7 Scroll the history list up by 7 rows (minimum position 1)
F8 Scroll the history list down by 7 rows
F12 Exit the transaction
Any other key Show the help message USE F1 F3 F7 F8 OR F12

1.2 Outcome Summary

Result HIST_CHECK_STATUS APPLICATION_STATUS Screen result
Pass P HC (history check passed) PASS, message HISTORY CHECK PASSED
Fail F RE (rejected) FAIL, plus the failure reason

5.2 Session Control (MAIN-LOGIC)

On first entry (EIBCALEN = 0) the program sends a blank map and returns to CICS with the same transaction ID. On later entries it restores the COMMAREA and processes the key that was pressed.

COBOL 
IF EIBCALEN = 0
    PERFORM INIT-SCREEN
ELSE
    MOVE DFHCOMMAREA TO DLIS-COMMAREA
    PERFORM PROCESS-INPUT
END-IF

5.3 Key Routing (PROCESS-INPUT)

COBOL 
EVALUATE TRUE
    WHEN EIBAID = DFHPF1   PERFORM RUN-HISTORY-CHECK
    WHEN EIBAID = DFHPF3   PERFORM LOAD-APPLICATION
    WHEN EIBAID = DFHPF7
        SUBTRACT 7 FROM WS-SCROLL-TOP
        IF WS-SCROLL-TOP < 1 MOVE 1 TO WS-SCROLL-TOP
        PERFORM DISPLAY-HISTORY
    WHEN EIBAID = DFHPF8
        ADD 7 TO WS-SCROLL-TOP
        PERFORM DISPLAY-HISTORY
    WHEN EIBAID = DFHPF12
        EXEC CICS RETURN END-EXEC
    OTHER
        MOVE 'USE F1 F3 F7 F8 OR F12' TO DHCMSG
END-EVALUATE

After the EVALUATE, the map is resent with DATAONLY FREEKB. The program then issues EXEC CICS RETURN TRANSID('DL06') COMMAREA(DLIS-COMMAREA) LENGTH(350).

5.4 Loading the Application (LOAD-APPLICATION, F3)

The paragraph first checks that an application ID was entered. It then joins the application and candidate tables.

COBOL 
IF DHCAIDI = ZEROS
    MOVE 'ENTER APPLICATION ID' TO DHCMSG
    GO TO LOAD-APP-EXIT
END-IF

MOVE DHCAIDI TO APPLICATION-ID OF DCLDLIS-LICENSE-APPL
EXEC SQL
    SELECT A.CANDIDATE_ID, A.LICENSE_TYPE,
           C.FIRST_NAME, C.LAST_NAME
    INTO   :CANDIDATE-ID OF DCLDLIS-LICENSE-APPL,
           :LICENSE-TYPE OF DCLDLIS-LICENSE-APPL,
           :FIRST-NAME, :LAST-NAME OF DCLDLIS-CANDIDATE
    FROM   DLIS.LICENSE_APPLICATION A
    JOIN   DLIS.CANDIDATE C
       ON  A.CANDIDATE_ID = C.CANDIDATE_ID
    WHERE  A.APPLICATION_ID = :APPLICATION-ID
                              OF DCLDLIS-LICENSE-APPL
END-EXEC
IF SQLCODE = 100
    MOVE 'APPLICATION NOT FOUND' TO DHCMSG
    GO TO LOAD-APP-EXIT
END-IF

On success the candidate name is built as first name, one space, then last name. The licence type is copied to the screen. LOAD-HISTORY-TABLE and DISPLAY-HISTORY then run, and the message APPLICATION LOADED is shown.

COBOL 
STRING FIRST-NAME OF DCLDLIS-CANDIDATE DELIMITED SPACE
       ' ' DELIMITED SIZE
       LAST-NAME  OF DCLDLIS-CANDIDATE DELIMITED SPACE
    INTO DHCCNAMO
MOVE LICENSE-TYPE OF DCLDLIS-LICENSE-APPL TO DHCLTYO

5.5 Loading the History (LOAD-HISTORY-TABLE)

The program resets the accumulators (WS-ROW-COUNT and WS-DEMERIT-TOTAL to 0, WS-SUSP-FLAG and WS-FINE-FLAG to N). It then reads the active incidents through cursor HISTCUR.

SQL 
DECLARE HISTCUR CURSOR FOR
    SELECT INCIDENT_DATE, INCIDENT_TYPE, INCIDENT_DESC,
           DEMERIT_POINTS, FINE_AMOUNT, FINE_PAID_STATUS,
           SUSP_START_DATE, SUSP_END_DATE
    FROM   DLIS.DRIVING_HISTORY
    WHERE  CANDIDATE_ID  = :CANDIDATE-ID
    AND    RECORD_STATUS = 'A'
    ORDER BY INCIDENT_DATE DESC
graph TD A[Reset counters and flags] --> B[OPEN HISTCUR] B --> C{FETCH
SQLCODE = 0?} C -- No --> H[CLOSE HISTCUR
Move totals to map fields] C -- Yes --> D[Increment WS-ROW-COUNT
Store row if count <= 50
Add demerit points] D --> E{Type SU or DQ and
end date >= today or blank?} E -- Yes --> F[WS-SUSP-FLAG = Y] E -- No --> G F --> G{FINE-AMOUNT > 0
and FINE-PAID-STATUS = N?} G -- Yes --> G1[WS-FINE-FLAG = Y] G -- No --> C G1 --> C
COBOL 
IF SQLCODE = 0
    ADD 1 TO WS-ROW-COUNT
    IF WS-ROW-COUNT <= 50
        MOVE INCIDENT-DATE  OF DCLDLIS-DRIVING-HIST
            TO WS-HR-DATE(WS-ROW-COUNT)
        MOVE INCIDENT-TYPE  OF DCLDLIS-DRIVING-HIST
            TO WS-HR-TYPE(WS-ROW-COUNT)

            TO WS-HR-DESC(WS-ROW-COUNT)

    END-IF

Suspension and disqualification detection:

COBOL 
IF INCIDENT-TYPE OF DCLDLIS-DRIVING-HIST IN ('SU','DQ')
    IF SUSP-END-DATE OF DCLDLIS-DRIVING-HIST >= CURRENT-DATE(1:10)
       OR SUSP-END-DATE OF DCLDLIS-DRIVING-HIST = SPACES
        MOVE 'Y' TO WS-SUSP-FLAG
    END-IF
END-IF

(The inventory source shows this line truncated; the intent is a comparison with the first 10 characters of CURRENT-DATE.)

Unpaid fine detection:

COBOL 
IF FINE-AMOUNT OF DCLDLIS-DRIVING-HIST > 0
    IF FINE-PAID-STATUS OF DCLDLIS-DRIVING-HIST = 'N'
        MOVE 'Y' TO WS-FINE-FLAG
    END-IF
END-IF

Summary indicators for the screen:

COBOL 
MOVE WS-DEMERIT-TOTAL TO DHCDMRTO
MOVE WS-SUSP-FLAG     TO DHCSUSPO
MOVE WS-FINE-FLAG     TO DHCFINEO.

5.6 Displaying the History (DISPLAY-HISTORY)

The paragraph clears the seven map lines DHCHL1O – DHCHL7O. A PERFORM VARYING loop starting at WS-SCROLL-TOP then fills up to seven lines. Each line is built with STRING from WS-HR-DATE, WS-HR-TYPE and the first 30 characters of WS-HR-DESC. The loop is bounded by UNTIL WS-SCROLL-TOP > WS-ROW-COUNT OR WS-SCROLL-TOP > 7. F7 and F8 move WS-SCROLL-TOP by 7 before this paragraph runs.

5.7 Running the History Check (RUN-HISTORY-CHECK, F1)

graph TD A[F1 pressed] --> B{Application ID entered?} B -- No --> B1[ENTER APPLICATION ID FIRST] B -- Yes --> C[PERFORM LOAD-APPLICATION] C --> D{DHCMSG = APPLICATION LOADED?} D -- No --> X[RUN-HIST-EXIT] D -- Yes --> E[SELECT ELIG_CHECK_STATUS] E --> F{ELIG_CHECK_STATUS = P?} F -- No --> F1[ELIGIBILITY CHECK MUST BE PASSED FIRST] F -- Yes --> G{WS-SUSP-FLAG = Y?} G -- Yes --> G1[Fail: ACTIVE SUSPENSION OR DISQUALIFICATION ON FILE] G -- No --> H{Demerit total > 12?} G1 --> H H -- Yes, no prior fail --> H1[Fail: TOTAL DEMERIT POINTS EXCEED THRESHOLD OF 12] H -- No --> I{WS-FINE-FLAG = Y?} H1 --> I I -- Yes, no prior fail --> I1[Fail: OUTSTANDING UNPAID FINES ON FILE] I -- No --> J{WS-FAIL-FLAG = Y?} I1 --> J J -- Yes --> K[Status F / RE
Map shows FAIL and reason] J -- No --> L[Status P / HC
Map shows PASS] K --> M[UPDATE LICENSE_APPLICATION] L --> M M --> N[Show result message]

Eligibility gate:

COBOL 
EXEC SQL
    SELECT ELIG_CHECK_STATUS
    INTO   :ELIG-CHECK-STATUS OF DCLDLIS-LICENSE-APPL
    FROM   DLIS.LICENSE_APPLICATION
    WHERE  APPLICATION_ID = :APPLICATION-ID
                            OF DCLDLIS-LICENSE-APPL
END-EXEC
IF ELIG-CHECK-STATUS OF DCLDLIS-LICENSE-APPL NOT = 'P'
    MOVE 'ELIGIBILITY CHECK MUST BE PASSED FIRST' TO DHCMSG
    GO TO RUN-HIST-EXIT
END-IF

Prioritised rule evaluation. Each later rule fires only if WS-FAIL-FLAG is still N, so only the first failure reason is kept:

COBOL 
MOVE SPACES TO WS-HIST-FAIL-MSG
MOVE 'N'    TO WS-FAIL-FLAG
IF WS-SUSP-FLAG = 'Y'
    MOVE 'Y' TO WS-FAIL-FLAG
    MOVE 'ACTIVE SUSPENSION OR DISQUALIFICATION ON FILE'
        TO WS-HIST-FAIL-MSG
END-IF
IF WS-DEMERIT-TOTAL > 12 AND WS-FAIL-FLAG = 'N'
    MOVE 'Y' TO WS-FAIL-FLAG
    MOVE 'TOTAL DEMERIT POINTS EXCEED THRESHOLD OF 12'
        TO WS-HIST-FAIL-MSG
END-IF
IF WS-FINE-FLAG = 'Y' AND WS-FAIL-FLAG = 'N'
    MOVE 'Y' TO WS-FAIL-FLAG
    MOVE 'OUTSTANDING UNPAID FINES ON FILE'
        TO WS-HIST-FAIL-MSG
END-IF
Priority Condition Failure message
1 WS-SUSP-FLAG = 'Y' ACTIVE SUSPENSION OR DISQUALIFICATION ON FILE
2 WS-DEMERIT-TOTAL > 12 TOTAL DEMERIT POINTS EXCEED THRESHOLD OF 12
3 WS-FINE-FLAG = 'Y' OUTSTANDING UNPAID FINES ON FILE

Outcome and persistence:

COBOL 
IF WS-FAIL-FLAG = 'Y'
    MOVE 'F'  TO WS-HISTORY-STATUS
    MOVE 'FAIL' TO DHCHSTSO
    MOVE WS-HIST-FAIL-MSG TO DHCHSDSO
    MOVE 'RE' TO APPLICATION-STATUS OF DCLDLIS-LICENSE-APPL
ELSE
    MOVE 'P'  TO WS-HISTORY-STATUS
    MOVE 'PASS' TO DHCHSTSO
    MOVE SPACES  TO DHCHSDSO
    MOVE 'HC' TO APPLICATION-STATUS OF DCLDLIS-LICENSE-APPL
END-IF

EXEC SQL
    UPDATE DLIS.LICENSE_APPLICATION SET
        HIST_CHECK_STATUS  = :WS-HISTORY-STATUS,
        HIST_CHECK_DATE    = CURRENT DATE,
        HIST_CHECK_NOTES   = :WS-HIST-FAIL-MSG,
        APPLICATION_STATUS = :APPLICATION-STATUS
                             OF DCLDLIS-LICENSE-APPL,
        LAST_UPDATED_DATE  = CURRENT DATE,
        LAST_UPDATED_BY    = EIBTRMID
    WHERE APPLICATION_ID   = :APPLICATION-ID
                             OF DCLDLIS-LICENSE-APPL
END-EXEC

Final message:

COBOL 
IF WS-HISTORY-STATUS = 'P'
    MOVE 'HISTORY CHECK PASSED' TO DHCMSG
ELSE
    MOVE WS-HIST-FAIL-MSG TO DHCMSG
END-IF.

7.2 Rule Details

Function Rule Key logic Why it matters
Session control Initial vs returning session EIBCALEN = 0 sends a fresh screen. Otherwise the program processes input. Prevents processing uninitialised input
Session control Function key routing F1, F3, F7, F8 and F12 are mapped to actions. Anything else gets guidance. A browse never triggers a status update
Intake Application ID required Zero ID gives ENTER APPLICATION ID (F3) or ENTER APPLICATION ID FIRST (F1). No lookup or status change without a target record
Intake Retrieve and display applicant A join on candidate ID gives the name and licence type. SQLCODE 100 gives APPLICATION NOT FOUND. The reviewer knows whose history is being assessed
History assessment Demerit accumulation Points are summed per stored row. Feeds the threshold test
History assessment Suspension detection Type SU/DQ with end date on or after today, or blank. Blocks licensing of a barred driver
History assessment Unpaid fines FINE-AMOUNT > 0 and FINE-PAID-STATUS = 'N'. Blocks applicants with outstanding fines
Decisioning Eligibility gate ELIG_CHECK_STATUS must be P. Enforces the workflow order
Decisioning Prioritised evaluation Suspension, then demerits above 12, then fines. The first failure wins. Gives one consistent, recorded reason
Decisioning Outcome recording Fail gives F/RE. Pass gives P/HC. Date, notes and terminal ID are saved. Provides an audit trail and advances the lifecycle

8. Error Handling

Condition Handling User feedback
Application ID is zero (F3) GO TO LOAD-APP-EXIT ENTER APPLICATION ID
Application ID is zero (F1) GO TO RUN-HIST-EXIT ENTER APPLICATION ID FIRST
SQLCODE = 100 on lookup GO TO LOAD-APP-EXIT APPLICATION NOT FOUND
Load did not return APPLICATION LOADED (F1) GO TO RUN-HIST-EXIT The load message remains
Eligibility not P GO TO RUN-HIST-EXIT, no update ELIGIBILITY CHECK MUST BE PASSED FIRST
Unrecognised key OTHER branch of the EVALUATE USE F1 F3 F7 F8 OR F12
End of cursor PERFORM UNTIL SQLCODE NOT = 0 ends the loop None (normal)
Negative SQLCODE Not trapped, so the loop ends silently None
CICS SEND/RECEIVE errors RESP(WS-RESP1) captured but never tested None

The RESP(WS-RESP1) option prevents an automatic abend on map errors, but the program does not act on the value. The following points are worth knowing:

  • The SQL UPDATE result is not checked. The pass or fail message is shown even if the update fails.
  • Negative SQL codes on SELECT, cursor and UPDATE statements produce no message or log entry.

9. Constraints and Known Behaviours

9.1 Workflow Constraints

  • The history check requires ELIG_CHECK_STATUS = 'P'.
  • Both the load and the check require a non-zero application ID.
  • The only status outcomes written are RE (rejected) on a fail and HC (history check passed) on a pass.

9.2 Data and Capacity Constraints

  • Only active history rows (RECORD_STATUS = 'A') are read.
  • WS-HIST-TABLE holds at most 50 rows (OCCURS 50 TIMES).
  • The map shows 7 history lines at a time.
  • The demerit threshold is 12. A total above 12 fails.
  • The demerit total is accumulated inside the WS-ROW-COUNT <= 50 guard, so it covers only the first 50 rows. The business-rule description says rows beyond 50 should still be counted. The code shown does not do this.

9.3 Known Implementation Characteristics

  • Scroll loop limit. The display loop condition WS-SCROLL-TOP > 7 means the list renders correctly only while the scroll position is 7 or less. Later pages show blank lines. The loop also changes WS-SCROLL-TOP.
  • State is not preserved between interactions. WS-SCROLL-TOP and WS-HIST-TABLE are in Working-Storage and are not saved in the COMMAREA. Each task starts with a scroll position of 1 and an empty table. After F7 or F8, the screen may therefore come back with blank lines until the history is reloaded with F3. The COMMAREA is passed back as it was received.
  • Status code naming. Some business-rule text describes RE as “referred”. The program description and screen flow treat it as rejected.

10. Examples

10.1 F1 on a Clean History (PASS)

Input: application 1001, candidate 501, licence type C, ELIG_CHECK_STATUS = 'P'.

INCIDENT_DATE TYPE DEMERIT_POINTS FINE_AMOUNT FINE_PAID_STATUS SUSP_END_DATE
2023-08-14 SP 3 150.00 Y blank
2021-03-02 SP 3 0 blank blank

Output:

  • DHCHSTSO = PASS, DHCHSDSO = spaces.
  • DHCDMRTO = 6, DHCSUSPO = N, DHCFINEO = N.
  • DHCMSG = HISTORY CHECK PASSED.
  • The record is updated with HIST_CHECK_STATUS = 'P', APPLICATION_STATUS = 'HC' and blank notes.

10.2 F1 with an Active Suspension and Too Many Points (FAIL)

Input: application 1002, ELIG_CHECK_STATUS = 'P'.

INCIDENT_DATE TYPE DEMERIT_POINTS FINE_AMOUNT FINE_PAID_STATUS SUSP_END_DATE
2024-01-10 SU 6 0 blank blank (open-ended)
2022-06-05 SP 4 200.00 N blank
2020-09-21 SP 4 0 blank blank

Output:

  • DHCHSTSO = FAIL.
  • DHCHSDSO and DHCMSG = ACTIVE SUSPENSION OR DISQUALIFICATION ON FILE.
  • DHCDMRTO = 14, DHCSUSPO = Y, DHCFINEO = Y.
  • The record is updated with HIST_CHECK_STATUS = 'F' and APPLICATION_STATUS = 'RE'.

All three failure conditions are true. Only the highest-priority reason is reported and stored.

10.3 F1 Before Eligibility Has Been Passed

Input: application 1003 with ELIG_CHECK_STATUS other than P.

Output: DHCMSG = ELIGIBILITY CHECK MUST BE PASSED FIRST. No UPDATE is issued and the application status is unchanged.

10.4 F3 Lookup and History Display

Input: application 1001 (candidate John Smith, licence type C, with the two incidents from section 10.1).

Output:

  • DHCCNAMO = John Smith, DHCLTYO = C.
  • DHCHL1O = 2023-08-14 SP <first 30 chars of description>.
  • DHCHL2O = 2021-03-02 SP <first 30 chars of description>.
  • DHCHL3O – DHCHL7O = spaces.
  • DHCDMRTO = 6, DHCSUSPO = N, DHCFINEO = N.
  • DHCMSG = APPLICATION LOADED.
