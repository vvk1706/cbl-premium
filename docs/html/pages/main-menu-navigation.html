Main Menu & Navigation (DL01)

The DLISMENU program is the central navigation hub of the Driver License Information System (DLIS), operating under CICS transaction ID DL01. It presents a numbered BMS map screen (DLISMM01) to terminal operators and routes selections to one of ten downstream functional programs via EXEC CICS XCTL. Session context is preserved across all interactions through a shared 350-byte communication area (DLIS-COMMAREA), following the CICS pseudo-conversational programming model.

1. Overview

DLISMENU serves as the single entry point for all DLIS business functions. When an operator starts transaction DL01 at a 3270 terminal, the program displays a numbered menu with up to ten options covering the full lifecycle of a driver license — from candidate registration through eligibility checking, payment processing, dual-authority approvals, and final license issuance.

The program is designed as a pseudo-conversational application: it terminates after each screen interaction and is re-invoked by CICS only when the operator presses an AID key, releasing system resources between interactions. Each re-invocation receives the preserved session state (candidate ID, application ID, user ID, messages, etc.) via a CICS COMMAREA, ensuring workflow continuity across the full menu-driven session.

Key characteristics:

  • Transaction ID: DL01
  • BMS Map / Mapset: DLISMM01 / DLISMM
  • Communication Area: DLIS-COMMAREA, fixed at 350 bytes
  • Navigation Model: EXEC CICS XCTL for forward routing; EXEC CICS RETURN TRANSID('DL01') for pseudo-conversational re-entry
  • No direct database access — DLISMENU is a pure navigation program

2. System Architecture

DLISMENU sits at the apex of the DLIS program hierarchy. All ten functional sub-programs are reachable exclusively through this menu, and each receives the shared DLIS-COMMAREA upon transfer of control. 3. Processing Logic

3.1 Execution Flow Overview

DLISMENU follows a strict two-phase pseudo-conversational cycle. On the very first invocation there is no COMMAREA, so the program initialises and paints a clean menu screen. On every subsequent invocation a 350-byte COMMAREA is present, and the program processes the operator’s input before either redisplaying the menu or transferring control to a downstream program.

3.2 Phase 1 — Initial Screen Presentation (INIT-SCREEN)

When EIBCALEN = 0 at MAIN-LOGIC, no prior COMMAREA exists and this is a cold start. The program:

  1. Moves the system current date into map field DMMDATE.
  2. Clears the message field DMMMSG to spaces.
  3. Issues EXEC CICS SEND MAP with ERASE FREEKB — erasing the terminal screen and unlocking the keyboard.
  4. Issues EXEC CICS RETURN TRANSID('DL01') COMMAREA(DLIS-COMMAREA) LENGTH(350) to suspend the task and re-queue DL01 for the operator’s next key press.
COBOL 
*  INIT-SCREEN — First invocation: paint the menu and wait
    MOVE FUNCTION CURRENT-DATE(1:10) TO DMMDATE
    MOVE SPACES                      TO DMMMSG
    EXEC CICS SEND MAP('DLISMM01')
              MAPSET('DLISMM')
              ERASE
              FREEKB
    END-EXEC
    EXEC CICS RETURN TRANSID('DL01')
              COMMAREA(DLIS-COMMAREA)
              LENGTH(350)
    END-EXEC

3.3 Phase 2 — Input Processing (PROCESS-INPUT)

On any re-entry (EIBCALEN > 0), the 350-byte DFHCOMMAREA is first moved into DLIS-COMMAREA, then the program reads the terminal input and validates it through three sequential gates:

Gate 1 — COMMAREA restoration:

COBOL 
*  MAIN-LOGIC — Restore session context on re-entry
    IF EIBCALEN = 0
        PERFORM INIT-SCREEN
    ELSE
        MOVE DFHCOMMAREA TO DLIS-COMMAREA
        PERFORM PROCESS-INPUT
    END-IF

Gate 2 — AID key validation:

COBOL 
*  PROCESS-INPUT — PF12 exits cleanly; only ENTER proceeds
    IF EIBAID = DFHPF12
        EXEC CICS RETURN END-EXEC
    END-IF
    IF EIBAID NOT = DFHENTER
        MOVE 'PRESS ENTER TO SELECT OR F12 TO EXIT' TO DMMMSG
        PERFORM REDISPLAY-MENU
    END-IF

Gate 3 — Option field validation:

COBOL 
*  PROCESS-INPUT — Blank option guard
    IF DMMOPTI = SPACES OR DMMOPTI = LOW-VALUES
        MOVE 'PLEASE SELECT AN OPTION (1-10)' TO DMMMSG
        PERFORM REDISPLAY-MENU
    END-IF

3.4 Option Routing (EVALUATE DMMOPTI)

Once the input passes all validation gates, the EVALUATE statement maps the entered option to its target program and transfers control via EXEC CICS XCTL:

COBOL 
EVALUATE DMMOPTI
        WHEN '1'  EXEC CICS XCTL PROGRAM('DLISCAND')
                      COMMAREA(DLIS-COMMAREA) LENGTH(350)
                  END-EXEC
        WHEN '2'  EXEC CICS XCTL PROGRAM('DLISCAND')
                      COMMAREA(DLIS-COMMAREA) LENGTH(350)
                  END-EXEC
        WHEN '3'  EXEC CICS XCTL PROGRAM('DLISAPPL')
                      COMMAREA(DLIS-COMMAREA) LENGTH(350)
                  END-EXEC
        WHEN '4'  EXEC CICS XCTL PROGRAM('DLISSTAT')
                      COMMAREA(DLIS-COMMAREA) LENGTH(350)
                  END-EXEC
        WHEN '5'  EXEC CICS XCTL PROGRAM('DLISELIG')
                      COMMAREA(DLIS-COMMAREA) LENGTH(350)
                  END-EXEC
        WHEN '6'  EXEC CICS XCTL PROGRAM('DLISHIST')
                      COMMAREA(DLIS-COMMAREA) LENGTH(350)
                  END-EXEC
        WHEN '7'  EXEC CICS XCTL PROGRAM('DLISPAY')
                      COMMAREA(DLIS-COMMAREA) LENGTH(350)
                  END-EXEC
        WHEN '8'  EXEC CICS XCTL PROGRAM('DLISAP1')
                      COMMAREA(DLIS-COMMAREA) LENGTH(350)
                  END-EXEC
        WHEN '9'  EXEC CICS XCTL PROGRAM('DLISAP2')
                      COMMAREA(DLIS-COMMAREA) LENGTH(350)
                  END-EXEC
        WHEN '10' EXEC CICS XCTL PROGRAM('DLISISSU')
                      COMMAREA(DLIS-COMMAREA) LENGTH(350)
                  END-EXEC
        OTHER
            MOVE 'INVALID OPTION. PLEASE SELECT 1-10' TO DMMMSG
            PERFORM REDISPLAY-MENU
    END-EVALUATE

3.5 Error Redisplay (REDISPLAY-MENU)

All three validation failure paths converge on REDISPLAY-MENU, which uses DATAONLY to refresh only dynamic map fields (avoiding a full screen repaint) and re-arms the pseudo-conversational cycle:

COBOL 
*  REDISPLAY-MENU — Efficient refresh with error message
    EXEC CICS SEND MAP('DLISMM01')
              MAPSET('DLISMM')
              DATAONLY
              FREEKB
    END-EXEC
    EXEC CICS RETURN TRANSID('DL01')
              COMMAREA(DLIS-COMMAREA)
              LENGTH(350)
    END-EXEC

4. Inputs

4.1 CICS Communication Area (DFHCOMMAREA / DLIS-COMMAREA)

DFHCOMMAREA is a 350-byte Linkage Section field injected by CICS on every pseudo-conversational re-entry. Its contents are immediately moved into DLIS-COMMAREA for structured processing.

Field Type Description
CA-TRANSACTION-ID PIC X(4) 4-character CICS transaction ID of the originating transaction
CA-RETURN-SCREEN PIC X(8) Program name identifying the return screen after navigation
CA-CANDIDATE-ID Packed decimal Identifier of the candidate record in the current session
CA-APPLICATION-ID Packed decimal Identifier of the license application record in context
CA-LICENSE-ID Packed decimal Identifier of the issued license record in context
CA-PAYMENT-ID Packed decimal Identifier of the payment record in context
CA-USER-ID PIC X(8) CICS user ID of the currently operating terminal operator
CA-RETURN-CODE Numeric Return code set by a previously executed program
CA-MSG-TEXT PIC X(78) 78-character message text passed back from a prior program
CA-MSG-COLOR PIC X(5) Display color attribute accompanying the message text
CA-ACTION PIC X(1) Single-character action code for the last operation

4.2 BMS Map Input

Field Map Description
DMMOPTI DLISMM01 User-entered menu option ('1'–'10'), the primary routing driver

4.3 CICS Execution Interface Block (EIB)

Field Usage
EIBCALEN Distinguishes first invocation (= 0) from pseudo-conversational re-entry (> 0)
EIBAID Identifies the AID key pressed — DFHPF12 exits; DFHENTER proceeds; all others are rejected

5. Outputs

5.1 BMS Map Outputs

Field Description
DMMDATE Current system date placed on the map header during INIT-SCREEN
DMMMSG Status, error, and guidance messages displayed to the operator

Map transmission modes:

  • ERASE FREEKB — Used on initial display; clears the entire 3270 screen before painting the menu.
  • DATAONLY FREEKB — Used on error redisplay; refreshes only the dynamic data fields, preserving screen layout.

5.2 Program Control Outputs

Target Program Option(s) Business Function
DLISCAND 1, 2 Candidate Registration / Candidate Search & Maintenance
DLISAPPL 3 License Application Entry
DLISSTAT 4 Application Status Inquiry
DLISELIG 5 Eligibility Check
DLISHIST 6 Driving History Review
DLISPAY 7 Fee Payment Processing
DLISAP1 8 First-Level Authority Approval
DLISAP2 9 Second-Level Authority Approval
DLISISSU 10 License Issuance

All XCTL transfers pass the full 350-byte DLIS-COMMAREA, and control never returns to DLISMENU — XCTL is a one-way transfer.

7. Business Rules

7.1 Session Entry and Context Continuity

Rule: Initial Session Detection and Communication Area Restoration

The program uses EIBCALEN as the authoritative indicator of session state:

EIBCALEN Value Interpretation Action
= 0 First (cold) invocation Perform INIT-SCREEN — display fresh menu
> 0 Pseudo-conversational re-entry Move DFHCOMMAREA → DLIS-COMMAREA, perform PROCESS-INPUT

Misidentifying a first entry as a re-entry would cause the program to process against an empty or invalid context. Failing to restore the COMMAREA on re-entry would break session continuity for all downstream programs.

7.2 Menu Input Validation

Rule: Only ENTER and PF12 Are Accepted AID Keys

The program enforces a two-key policy on the menu screen. ENTER submits the selection; PF12 terminates the session. All other AID keys (PF1–PF11, PF13–PF24, PA keys, CLEAR) produce a guidance message and redisplay:

CODE 
PRESS ENTER TO SELECT OR F12 TO EXIT

Rule: Mandatory Option Selection

An empty option field (SPACES or LOW-VALUES) is an absolute rejection. The program never routes on a blank entry:

CODE 
PLEASE SELECT AN OPTION (1-10)

7.3 Menu Option Routing

Rule: Menu Option Routing to Business Functions

Each valid option resolves to exactly one program. Options 1 and 2 both route to DLISCAND — they are structurally indistinguishable at routing time. Any option outside '1'–'10' triggers:

CODE 
INVALID OPTION. PLEASE SELECT 1-10

8. Paragraphs

8.1 MAIN-LOGIC

  • Purpose: Primary entry point and high-level controller for the pseudo-conversational execution cycle.
  • Operations: Inspects EIBCALEN, conditionally moves DFHCOMMAREA to DLIS-COMMAREA, delegates to INIT-SCREEN or PROCESS-INPUT, then halts with STOP RUN.
  • Control Flow: Single IF EIBCALEN = 0 … ELSE … END-IF branch.

8.2 INIT-SCREEN

  • Purpose: Initialises and displays the menu for the first invocation.
  • Operations: Populates DMMDATE, clears DMMMSG, issues SEND MAP … ERASE FREEKB, and returns pseudo-conversationally with TRANSID('DL01').

8.3 PROCESS-INPUT

  • Purpose: Receives terminal input, validates AID keys and menu options, and routes control to the appropriate sub-program.
  • Operations: Issues RECEIVE MAP, evaluates EIBAID and DMMOPTI, transfers via XCTL for valid options, or calls REDISPLAY-MENU for all validation failures.

8.4 REDISPLAY-MENU

  • Purpose: Refreshes the terminal screen with an error message while retaining static screen elements.
  • Operations: Issues SEND MAP … DATAONLY FREEKB, then returns pseudo-conversationally with TRANSID('DL01') and the current COMMAREA.

10. Error Handling

10.1 Input Validation and User Notification

All user-facing errors are surfaced through the single DMMMSG field on map DLISMM01. There are three distinct error messages:

Condition Message Displayed
AID key is not ENTER or PF12 PRESS ENTER TO SELECT OR F12 TO EXIT
Option field is blank / LOW-VALUES PLEASE SELECT AN OPTION (1-10)
Option value is outside '1'–'10' INVALID OPTION. PLEASE SELECT 1-10

Every error path terminates in REDISPLAY-MENU, which sends the updated message and returns pseudo-conversationally — the operator always gets another chance to correct input.

10.2 CICS Response Handling

The SEND MAP and RECEIVE MAP commands specify WS-RESP1 to suppress the default CICS abend on conditions such as MAPFAIL. However, WS-RESP1 is never tested after either command — a MAPFAIL or receive error would be silently ignored and processing would continue against potentially stale or empty map data.

10.3 Transfer of Control

All ten EXEC CICS XCTL calls carry no RESP option and no HANDLE ABEND. If a target program is not found or not enabled, CICS applies its default abend behavior. There is no user-friendly recovery path for routing failures.

10.4 Known Gaps and Limitations

  • No validation is performed on COMMAREA content or field values beyond the zero-length check.
  • The fixed 350-byte COMMAREA length is hardcoded in all RETURN and XCTL calls with no runtime size check.
  • Option '10' is a two-character literal; depending on the BMS map field definition for DMMOPT, it may be unreachable if the field is defined as a single character.
  • No retry counters, error logging, MQ operations, or abend-handling routines are present.
  • The SQL Communication Area (SQLCA) is compiled in via DLISWS.cpy but no SQL is executed in this program.

11. Examples

11.1 Example 1 — First Entry to Transaction DL01

Scenario: An operator starts DL01 from a blank terminal.

Inputs:

  • EIBCALEN = 0 (no COMMAREA)

Expected Behavior:

  1. MAIN-LOGIC detects EIBCALEN = 0 and performs INIT-SCREEN.
  2. DMMDATE is populated with the current date; DMMMSG is cleared.
  3. Map DLISMM01 is sent with ERASE FREEKB.
  4. EXEC CICS RETURN TRANSID('DL01') COMMAREA(DLIS-COMMAREA) LENGTH(350) suspends the task.

Result: The operator sees a clean menu screen with today’s date and an empty message line.

11.2 Example 2 — Valid Option Selected (Option 3)

Scenario: The operator types 3 in the option field and presses ENTER.

Inputs:

  • EIBCALEN = 350, EIBAID = DFHENTER, DMMOPTI = '3'

Expected Behavior:

  1. DFHCOMMAREA is moved to DLIS-COMMAREA.
  2. RECEIVE MAP reads DMMOPTI = '3'.
  3. EIBAID = DFHENTER passes both AID checks.
  4. DMMOPTI is not blank — passes empty field check.
  5. EVALUATE DMMOPTI WHEN '3' — XCTL to DLISAPPL with 350-byte COMMAREA.

Result: The operator is taken to the License Application Entry screen.

11.3 Example 3 — Blank or Invalid Selection

Scenario A: Operator presses ENTER without entering an option.

Input DMMOPTI = SPACES
Message PLEASE SELECT AN OPTION (1-10)
Screen Menu redisplayed with DATAONLY FREEKB

Scenario B: Operator enters 42 and presses ENTER.

Input DMMOPTI = '42'
Message INVALID OPTION. PLEASE SELECT 1-10
Screen Menu redisplayed with DATAONLY FREEKB

In both cases the task ends with RETURN TRANSID('DL01'), preserving session context for the retry.

11.4 Example 4 — Function Key Behavior

Scenario A: Operator presses PF12.

  • EIBAID = DFHPF12 triggers EXEC CICS RETURN with no TRANSID — the conversation ends cleanly.

Scenario B: Operator presses PF3 (or any other non-ENTER, non-PF12 key).

  • EIBAID ≠ DFHENTER — message PRESS ENTER TO SELECT OR F12 TO EXIT is set.
  • Menu is redisplayed; task returns to DL01 for the next input.
