Candidate Maintenance (DL02)

1. Overview

The Candidate Maintenance screen (transaction DL02) is a CICS/COBOL online application implemented by program DLISCAND. It provides a single 3270 terminal screen through which authorised users can create, update, inquire on, and deactivate candidate records held in the DLIS.CANDIDATE DB2 table.

The transaction operates in a pseudo-conversational pattern: after each user action the program stores its state in a 350-byte COMMAREA, issues a EXEC CICS RETURN TRANSID('DL02'), and waits for the next key press. The user selects an operation entirely through function keys — no menu navigation is required. F1 creates, F2 updates, F3 inquires, F4 deactivates, and F12 exits.

Before creating a record the program validates that first name, last name and national ID are all present, and checks that no active candidate already carries the same national ID. All outcomes — success, validation failure, duplicate detection, or database error — are communicated by a single message line on the same screen.

3. Processing Logic

3.1 High-Level Flow

The following diagram illustrates the end-to-end execution path, from transaction entry through function-key dispatch to database interaction and screen refresh.

graph TD A([Start — Transaction DL02 invoked]) --> B{EIBCALEN = 0?} B -- Yes: First entry --> C[INIT-SCREEN\nClear message, set date\nSend map with ERASE] C --> D[RETURN TRANSID DL02\nwith COMMAREA] B -- No: Return entry --> E[Copy DFHCOMMAREA\nto DLIS-COMMAREA] E --> F[RECEIVE MAP DLISCM01] F --> G{EIBAID — which key?} G -- F1 --> H[CREATE-CANDIDATE] G -- F2 --> I[UPDATE-CANDIDATE] G -- F3 --> J[INQUIRE-CANDIDATE] G -- F4 --> K[DEACTIVATE-CANDIDATE] G -- F12 --> L([RETURN — end session]) G -- Other --> M[Set invalid key message] H --> N[SEND MAP DATAONLY\nFREEKB] I --> N J --> N K --> N M --> N N --> O[RETURN TRANSID DL02\nwith COMMAREA] O --> Z([End of task]) D --> Z

3.2 Pseudo-Conversational State

The program never holds a conversation open. On every interaction it persists its state to the 350-byte DLIS-COMMAREA and exits, allowing CICS to free resources. The next key press re-enters the transaction, restores the COMMAREA, and resumes processing.

Key COMMAREA fields carried across interactions:

Field Purpose
CA-TRANSACTION-ID Identifies the running transaction (DL02)
CA-RETURN-SCREEN Target screen for navigation
CA-CANDIDATE-ID Current candidate in context
CA-USER-ID Operator identifier
CA-MESSAGE Last message text
CA-ACTION Last action performed

4. Function Key Operations

4.1 Function Key Reference

Key Operation Program Paragraph
F1 Create candidate CREATE-CANDIDATE
F2 Update candidate UPDATE-CANDIDATE
F3 Inquire on candidate INQUIRE-CANDIDATE
F4 Deactivate candidate DEACTIVATE-CANDIDATE
F12 Exit session PROCESS-INPUT (inline RETURN)
Any other Invalid key message PROCESS-INPUT (default branch)

The dispatch is performed in PROCESS-INPUT using an EVALUATE TRUE on EIBAID:

COBOL 
EVALUATE TRUE
               WHEN EIBAID = DFHPF1
                   PERFORM CREATE-CANDIDATE
               WHEN EIBAID = DFHPF2
                   PERFORM UPDATE-CANDIDATE
               WHEN EIBAID = DFHPF3
                   PERFORM INQUIRE-CANDIDATE
               WHEN EIBAID = DFHPF4
                   PERFORM DEACTIVATE-CANDIDATE
               WHEN EIBAID = DFHPF12
                   EXEC CICS RETURN END-EXEC
               OTHER
                   MOVE 'INVALID KEY - USE F1-F4 OR F12' TO DCMMSG
           END-EVALUATE

4.2 Session Entry Determination

On every task start, MAIN-LOGIC checks EIBCALEN to decide whether to show a blank screen or process input:

COBOL 
IF EIBCALEN = 0
               PERFORM INIT-SCREEN
           ELSE
               MOVE DFHCOMMAREA  TO DLIS-COMMAREA
               PERFORM PROCESS-INPUT
           END-IF

5.3 Required Field Validation Code

COBOL 
IF DCMFNAMI = SPACES OR DCMFNAMI = LOW-VALUES
               MOVE 'FIRST NAME IS REQUIRED' TO DCMMSG
               GO TO CREATE-CANDIDATE-EXIT
           END-IF
           IF DCMLNAMI = SPACES OR DCMLNAMI = LOW-VALUES
               MOVE 'LAST NAME IS REQUIRED' TO DCMMSG
               GO TO CREATE-CANDIDATE-EXIT
           END-IF
           IF DCMIDNOI = SPACES OR DCMIDNOI = LOW-VALUES
               MOVE 'NATIONAL ID IS REQUIRED' TO DCMMSG
               GO TO CREATE-CANDIDATE-EXIT
           END-IF

5.4 Duplicate Active Candidate Check

Before inserting, the program checks for an existing active record with the same national ID:

COBOL 
MOVE DCMIDNOI TO ID-NUMBER OF DCLDLIS-CANDIDATE
           EXEC SQL
               SELECT CANDIDATE_ID INTO :CANDIDATE-ID OF DCLDLIS-CANDIDATE
               FROM DLIS.CANDIDATE
               WHERE ID_NUMBER    = :ID-NUMBER OF DCLDLIS-CANDIDATE
               AND   RECORD_STATUS = 'A'
           END-EXEC
           IF SQLCODE = 0
               MOVE 'CANDIDATE WITH THIS ID NUMBER ALREADY EXISTS'
                   TO DCMMSG
               GO TO CREATE-CANDIDATE-EXIT
           END-IF

Note: Only active records (RECORD_STATUS = 'A') block re-registration. An inactive record with the same national ID does not prevent a new candidate from being created.

5.5 Insert and Identity Retrieval

COBOL 
MOVE DCMFNAMI  TO FIRST-NAME    OF DCLDLIS-CANDIDATE
           MOVE DCMLNAMI  TO LAST-NAME     OF DCLDLIS-CANDIDATE
           MOVE DCMDOBI   TO DATE-OF-BIRTH OF DCLDLIS-CANDIDATE
           MOVE DCMIDNOI  TO ID-NUMBER     OF DCLDLIS-CANDIDATE
           MOVE DCMADR1I  TO ADDRESS-LINE-1 OF DCLDLIS-CANDIDATE
           MOVE DCMADR2I  TO ADDRESS-LINE-2 OF DCLDLIS-CANDIDATE
           MOVE DCMCITYI  TO CITY          OF DCLDLIS-CANDIDATE
           MOVE DCMSTATI  TO STATE-PROVINCE OF DCLDLIS-CANDIDATE
           MOVE DCMPOSTI  TO POSTAL-CODE   OF DCLDLIS-CANDIDATE
           MOVE DCMCTRYI  TO COUNTRY       OF DCLDLIS-CANDIDATE
           MOVE DCMPHNI   TO PHONE-NUMBER  OF DCLDLIS-CANDIDATE
           MOVE DCMEMLI   TO EMAIL-ADDRESS OF DCLDLIS-CANDIDATE
           MOVE 'A'       TO RECORD-STATUS OF DCLDLIS-CANDIDATE
           MOVE EIBTRMID  TO CREATED-BY    OF DCLDLIS-CANDIDATE
           EXEC SQL
               INSERT INTO DLIS.CANDIDATE
                  (FIRST_NAME, LAST_NAME, DATE_OF_BIRTH, ID_NUMBER,
                   ADDRESS_LINE_1, ADDRESS_LINE_2, CITY,
                   STATE_PROVINCE, POSTAL_CODE, COUNTRY,
                   PHONE_NUMBER, EMAIL_ADDRESS, RECORD_STATUS, CREATED_BY)
               VALUES
                  (:FIRST-NAME, :LAST-NAME, :DATE-OF-BIRTH, :ID-NUMBER,
                   :ADDRESS-LINE-1, :ADDRESS-LINE-2, :CITY,
                   :STATE-PROVINCE, :POSTAL-CODE, :COUNTRY,
                   :PHONE-NUMBER, :EMAIL-ADDRESS, :RECORD-STATUS,
                   :CREATED-BY)
               OF DCLDLIS-CANDIDATE
           END-EXEC

After a successful insert, the system-generated ID is retrieved and shown:

COBOL 
EXEC SQL
               SELECT IDENTITY_VAL_LOCAL()
               INTO :CANDIDATE-ID OF DCLDLIS-CANDIDATE
               FROM SYSIBM.SYSDUMMY1
           END-EXEC
           MOVE CANDIDATE-ID OF DCLDLIS-CANDIDATE TO DCMCIDO
           MOVE 'CANDIDATE CREATED SUCCESSFULLY' TO DCMMSG

6. Update Candidate (F2)

6.1 Update Flow

The update operation requires the Candidate ID as the target key. The program updates name, address, contact details and record status in a single SQL statement.

graph TD A([F2 pressed]) --> B{Candidate ID\nentered?} B -- No --> ERR1[CANDIDATE ID IS REQUIRED\nFOR UPDATE → EXIT] B -- Yes --> C[Move DCMCIDI to CANDIDATE-ID] C --> D[UPDATE DLIS.CANDIDATE\nSET name, address, phone,\nemail, record_status\nWHERE CANDIDATE_ID = :CANDIDATE-ID] D --> E{SQLCODE?} E -- 100 --> MSG1[CANDIDATE NOT FOUND] E -- Non-zero --> MSG2[DATABASE ERROR ON UPDATE] E -- 0 --> MSG3[CANDIDATE UPDATED SUCCESSFULLY]

6.2 Update Code

COBOL 
MOVE DCMCIDI TO CANDIDATE-ID OF DCLDLIS-CANDIDATE
           EXEC SQL
               UPDATE DLIS.CANDIDATE SET
                  FIRST_NAME       = :FIRST-NAME,
                  LAST_NAME        = :LAST-NAME,
                  ADDRESS_LINE_1   = :ADDRESS-LINE-1,
                  ADDRESS_LINE_2   = :ADDRESS-LINE-2,
                  CITY             = :CITY,
                  STATE_PROVINCE   = :STATE-PROVINCE,
                  POSTAL_CODE      = :POSTAL-CODE,
                  COUNTRY          = :COUNTRY,
                  PHONE_NUMBER     = :PHONE-NUMBER,
                  EMAIL_ADDRESS    = :EMAIL-ADDRESS,
                  RECORD_STATUS    = :RECORD-STATUS
               WHERE CANDIDATE_ID  = :CANDIDATE-ID
               OF DCLDLIS-CANDIDATE
           END-EXEC
           IF SQLCODE = 100
               MOVE 'CANDIDATE NOT FOUND' TO DCMMSG
           ELSE IF SQLCODE NOT = 0
               MOVE 'DATABASE ERROR ON UPDATE' TO DCMMSG
           ELSE
               MOVE 'CANDIDATE UPDATED SUCCESSFULLY' TO DCMMSG
           END-IF

Column Host Variable Notes

⚠️ Known defect: The UPDATE paragraph does not move screen input fields into host variables before executing SQL. The values written to the database are whatever the host variables already hold from a previous operation, not what the user typed on the screen.

7. Inquire Candidate (F3)

7.1 Inquire Flow

graph TD A([F3 pressed]) --> B{Candidate ID = 0\nAND National ID = spaces?} B -- Yes --> ERR1[ENTER CANDIDATE ID\nOR NATIONAL ID → EXIT] B -- No --> C[Move DCMCIDI → CANDIDATE-ID\nMove DCMIDNOI → ID-NUMBER] C --> D["SELECT all columns\nFROM DLIS.CANDIDATE\nWHERE CANDIDATE_ID = :id\nOR ID_NUMBER = :nat_id\nFETCH FIRST 1 ROW ONLY"] D --> E{SQLCODE?} E -- 100 --> MSG1[CANDIDATE NOT FOUND → EXIT] E -- 0 --> F[Move all columns to\nscreen output fields\nDCMCIDO, DCMFNAMO etc.] F --> MSG2[CANDIDATE FOUND]

7.2 Inquiry SQL

COBOL 
MOVE DCMCIDI  TO CANDIDATE-ID OF DCLDLIS-CANDIDATE
           MOVE DCMIDNOI TO ID-NUMBER    OF DCLDLIS-CANDIDATE
           EXEC SQL
               SELECT CANDIDATE_ID, FIRST_NAME, LAST_NAME,
                      DATE_OF_BIRTH, ID_NUMBER, ADDRESS_LINE_1,
                      ADDRESS_LINE_2, CITY, STATE_PROVINCE,
                      POSTAL_CODE, COUNTRY, PHONE_NUMBER,
                      EMAIL_ADDRESS, RECORD_STATUS
               INTO   :CANDIDATE-ID, :FIRST-NAME, :LAST-NAME,
                      :DATE-OF-BIRTH, :ID-NUMBER, :ADDRESS-LINE-1,
                      :ADDRESS-LINE-2, :CITY, :STATE-PROVINCE,
                      :POSTAL-CODE, :COUNTRY, :PHONE-NUMBER,
                      :EMAIL-ADDRESS, :RECORD-STATUS
               OF DCLDLIS-CANDIDATE
               FROM DLIS.CANDIDATE
               WHERE CANDIDATE_ID = :CANDIDATE-ID
                  OR ID_NUMBER    = :ID-NUMBER
               OF DCLDLIS-CANDIDATE
               FETCH FIRST 1 ROW ONLY
           END-EXEC
           IF SQLCODE = 100
               MOVE 'CANDIDATE NOT FOUND' TO DCMMSG
               GO TO INQUIRE-CANDIDATE-EXIT
           END-IF

7.3 Inquiry Behaviour Notes

  • The search uses an OR condition: either Candidate ID or National ID can locate a record.
  • FETCH FIRST 1 ROW ONLY prevents a multi-row error when both keys match different rows.
  • The query does not filter on RECORD_STATUS, so both active and inactive candidates are returned.
  • The DCMSTSO screen field always reflects the true current status of the returned record.

8. Deactivate Candidate (F4)

8.1 Deactivate Flow

Deactivation is a soft delete: the row is never removed from DLIS.CANDIDATE. Instead, RECORD_STATUS is set to 'I' (inactive).

graph TD A([F4 pressed]) --> B{Candidate ID = 0?} B -- Yes --> ERR1[CANDIDATE ID IS REQUIRED\nTO DEACTIVATE → EXIT] B -- No --> C[Move DCMCIDI → CANDIDATE-ID] C --> D[UPDATE DLIS.CANDIDATE\nSET RECORD_STATUS = 'I'\nWHERE CANDIDATE_ID = :id] D --> E{SQLCODE?} E -- 100 --> MSG1[CANDIDATE NOT FOUND] E -- Non-zero --> MSG2[DATABASE ERROR ON DEACTIVATE] E -- 0 --> F[Set DCMSTSO = 'I'] F --> MSG3[CANDIDATE DEACTIVATED]

8.2 Deactivation Code

COBOL 
MOVE DCMCIDI TO CANDIDATE-ID OF DCLDLIS-CANDIDATE
           EXEC SQL
               UPDATE DLIS.CANDIDATE
               SET    RECORD_STATUS = 'I'
               WHERE  CANDIDATE_ID  = :CANDIDATE-ID OF DCLDLIS-CANDIDATE
           END-EXEC
           IF SQLCODE = 100
               MOVE 'CANDIDATE NOT FOUND' TO DCMMSG
           ELSE IF SQLCODE NOT = 0
               MOVE 'DATABASE ERROR ON DEACTIVATE' TO DCMMSG
           ELSE
               MOVE 'I' TO DCMSTSO
               MOVE 'CANDIDATE DEACTIVATED' TO DCMMSG
           END-IF

8.3 Deactivation Business Rules

  • RECORD_STATUS = 'I' is a logical delete — data is retained for audit and history.
  • A deactivated candidate is excluded from the active-duplicate check on subsequent F1 creates with the same national ID.
  • There is no dependency check: deactivation proceeds even if the candidate has linked applications, payments, or licences.
  • Deactivating an already-inactive candidate succeeds silently (no status guard in the SQL WHERE clause).

11.3 Error Handling Gaps

The following limitations exist in the current implementation:

  • CICS RESP codes from SEND MAP and RECEIVE MAP are stored in WS-RESP1 but never tested. A MAPFAIL condition (user pressed a key with no data) is silently ignored.
  • Negative SQLCODE values (deadlock, constraint violation, timeout) are not individually distinguished — all non-zero, non-100 codes produce a generic error message.
  • No explicit rollback is issued on failure. The program relies on the CICS syncpoint at task end.
  • IDENTITY_VAL_LOCAL() SQLCODE is not checked after the post-insert select.
  • No WHENEVER SQLERROR directive is present.
  • No audit logging to CICS TD/TS queues or error tables.

13. Usage Examples

13.1 Example: Create a Candidate (F1)

Screen input:

Field Value
First Name JOHN
Last Name SMITH
Date of Birth 1990-05-14
National ID A1234567
City BOSTON
Country USA
Terminal (EIBTRMID) T001

Expected outcome:

  • Message: CANDIDATE CREATED SUCCESSFULLY

13.2 Example: Create Rejected — Missing Field

Screen input: First Name JANE, Last Name (blank), National ID B7654321, key F1.

  • Message: LAST NAME IS REQUIRED
  • No SQL executed.

Screen input: First Name JOHN, Last Name SMITH, National ID A1234567, key F1.
An active record with ID_NUMBER = 'A1234567' already exists.

Expected outcome:

  • Message: CANDIDATE WITH THIS ID NUMBER ALREADY EXISTS
  • No INSERT executed.

13.4 Example: Inquire by Candidate ID (F3)

Screen input: Candidate ID 1001, National ID (blank), key F3.

Expected outcome:

  • Message: CANDIDATE FOUND
  • Screen fields populated: JOHN, SMITH, 1990-05-14, A1234567, BOSTON, USA, Status A

13.5 Example: Deactivate a Candidate (F4)

Screen input: Candidate ID 1001, key F4.

Expected outcome:

  • Message: CANDIDATE DEACTIVATED
  • DCMSTSO on screen: I
  • DB2 row: RECORD_STATUS = 'I' for candidate 1001
  • National ID A1234567 is now free for re-registration.
