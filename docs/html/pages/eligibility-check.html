Eligibility Check (DL05)

1. Overview

Eligibility Check (transaction DL05, program DLISELIG) is a CICS pseudo-conversational transaction in the Driver License Information System (DLIS). A licensing officer uses it to decide whether a candidate qualifies for the license type named on a license application.

The program evaluates two business rules:

  1. Minimum age. The candidate must be at least 16 for a Learner (L) license, 17 for Probation (P) and 18 for Open (O).
  2. Prerequisite active license (upgrade path). A Probation application requires an active Learner license. An Open application requires an active Probation license. A Learner application has no prerequisite.

The program then records the outcome on the application: the pass/fail result, the failure reason, the date, the checking officer and the new application status.

1.1 Key Capabilities

Capability Description
Application lookup (F3) Loads the application and candidate details (name, date of birth, license type, minimum age) onto the screen.
Eligibility check (F1) Runs the age and prerequisite rules and records the result.
Exit (F12) Ends the transaction.
Audit trail Writes the check date, the officer ID and the failure notes to the application record.

1.2 Outcome Summary

Outcome ELIG_CHECK_STATUS APPLICATION_STATUS Screen status Screen message
Pass P EC (eligibility cleared) PASS ELIGIBILITY CHECK PASSED
Fail F RE (rejected / eligibility failed) FAIL The failure reason text

2.1 Component Overview

3.1 Inputs

4. Processing Logic

4.1 Pseudo-Conversational Flow

Every execution ends with a CICS RETURN TRANSID('DL05') that passes the 350-byte COMMAREA. The exception is F12, which returns without a TRANSID and so ends the conversation.

SEND MAP ERASE FREEKB] C --> D[RETURN TRANSID DL05
COMMAREA 350] B -- No --> E[Move DFHCOMMAREA to DLIS-COMMAREA] E --> F[PROCESS-INPUT
RECEIVE MAP] F --> G{EIBAID} G -- F1 --> H[RUN-ELIGIBILITY-CHECK] G -- F3 --> I[LOAD-APPLICATION] G -- F12 --> J[RETURN without TRANSID] G -- Other --> K[USE F1 F3 OR F12] H --> L[SEND MAP DATAONLY FREEKB] I --> L K --> L L --> M[RETURN TRANSID DL05
COMMAREA 350] D --> Z([End of task]) M --> Z J --> Z

5. Business Rules

5.1 Age Calculation

Age is the current year minus the birth year. Month and day are ignored, so a candidate whose birthday falls later in the current year is treated as already having reached that age.

COBOL 
MOVE DATE-OF-BIRTH OF DCLDLIS-CANDIDATE(1:4)
               TO WS-DOB-YEAR
           MOVE CURRENT-DATE(1:4) TO WS-CURR-YEAR
           COMPUTE WS-CALC-AGE = WS-CURR-YEAR - WS-DOB-YEAR
           MOVE WS-CALC-AGE TO DECAGEO

5.2 Minimum Age by License Type

The fail flag and reason are initialised, then an EVALUATE applies the age threshold for the license type.

COBOL 
MOVE 'N' TO WS-FAIL-FLAG
           MOVE SPACES TO WS-ELIG-FAIL-REASON

      *    Age check
           EVALUATE LICENSE-TYPE OF DCLDLIS-LICENSE-APPL
               WHEN 'L'
                   IF WS-CALC-AGE < 16
                       MOVE 'Y' TO WS-FAIL-FLAG
                       MOVE 'AGE BELOW 16 - LEARNER LICENSE REQUIRES MIN
                           TO WS-ELIG-FAIL-REASON
                   END-IF
               WHEN 'P'
                   IF WS-CALC-AGE < 17
                       ...
               WHEN 'O'
                   IF WS-CALC-AGE < 18
                       ...
           END-EVALUATE

The age failure messages are truncated in the source (for example AGE BELOW 16 - LEARNER LICENSE REQUIRES MIN…).

5.3 Prerequisite License Checks

These checks run only if the age check has not already failed (WS-FAIL-FLAG = 'N'). That avoids unnecessary DB2 calls.

Probation applicants need an active Learner license

COBOL 
IF LICENSE-TYPE OF DCLDLIS-LICENSE-APPL = 'P'
                           AND WS-FAIL-FLAG = 'N'
               EXEC SQL
                   SELECT COUNT(*) INTO :WS-PRIOR-COUNT
                   FROM   DLIS.ISSUED_LICENSE
                   WHERE  CANDIDATE_ID   = :CANDIDATE-ID
                                           OF DCLDLIS-LICENSE-APPL
                   AND    LICENSE_TYPE   = 'L'
                   AND    LICENSE_STATUS = 'A'
               END-EXEC
               IF WS-PRIOR-COUNT = 0
                   MOVE 'Y' TO WS-FAIL-FLAG
                   MOVE 'MUST HOLD ACTIVE LEARNER LICENSE FOR PROBATION'
                       TO WS-ELIG-FAIL-REASON
               END-IF
           END-IF

Open applicants need an active Probation license

The structure is the same as above, with LICENSE_TYPE = 'P' and the reason MUST HOLD ACTIVE PROBATION LICENSE FOR OPEN.

5.4 Rule Summary

License type Minimum age Prerequisite (active) Failure reasons
Learner (L) 16 None Age below 16
Probation (P) 17 Learner (L, status A) Age below 17, or must hold active Learner license
Open (O) 18 Probation (P, status A) Age below 18, or must hold active Probation license

5.5 Determining and Persisting the Outcome

A single failure is enough to reject the application. The result is then written to the application record.

COBOL 
IF WS-FAIL-FLAG = 'Y'
               MOVE 'F' TO WS-ELIGIBILITY-STATUS
               MOVE 'FAIL'             TO DECESTSO
               MOVE WS-ELIG-FAIL-REASON TO DECENTSO
               MOVE 'RE'              TO APPLICATION-STATUS
                                         OF DCLDLIS-LICENSE-APPL
           ELSE
               MOVE 'P' TO WS-ELIGIBILITY-STATUS
               MOVE 'PASS' TO DECESTSO
               MOVE SPACES TO DECENTSO
               MOVE 'EC'   TO APPLICATION-STATUS
                               OF DCLDLIS-LICENSE-APPL
           END-IF
COBOL 
EXEC SQL
               UPDATE DLIS.LICENSE_APPLICATION SET
                   ELIG_CHECK_STATUS = :WS-ELIGIBILITY-STATUS,
                   ELIG_CHECK_DATE   = CURRENT DATE,
                   ELIG_CHECK_NOTES  = :WS-ELIG-FAIL-REASON,
                   APPLICATION_STATUS= :APPLICATION-STATUS
                                       OF DCLDLIS-LICENSE-APPL,
                   LAST_UPDATED_DATE = CURRENT DATE,
                   LAST_UPDATED_BY   = :DECCHKBYI
               WHERE APPLICATION_ID  = :APPLICATION-ID
                                       OF DCLDLIS-LICENSE-APPL
           END-EXEC

The UPDATE runs for both pass and fail, so the outcome and the audit trail are always stored. Afterwards DECMSG is set to ELIGIBILITY CHECK PASSED on a pass. On a fail it is set to the failure reason text.

6. Paragraph Reference

Paragraph Description
MAIN-LOGIC Entry point. Tests EIBCALEN. Performs INIT-SCREEN on first entry, otherwise restores the COMMAREA and performs PROCESS-INPUT.
INIT-SCREEN Moves the current date to DECDATE. Sends map DLISEC01 with ERASE FREEKB. Returns with TRANSID('DL05'), COMMAREA(DLIS-COMMAREA) and LENGTH(350).
PROCESS-INPUT Receives the map. Evaluates EIBAID for DFHPF1, DFHPF3, DFHPF12 or other. Sends the map with DATAONLY FREEKB and then returns pseudo-conversationally.
LOAD-APPLICATION Validates the Application ID. Runs the join SELECT. Handles SQLCODE = 100. Populates the screen fields.
LOAD-APPLICATION-EXIT EXIT target for GO TO within LOAD-APPLICATION.
RUN-ELIGIBILITY-CHECK Runs the input validation, application reload, age calculation, age rule, upgrade-path rules, result recording and DB2 UPDATE.
RUN-ELIG-EXIT EXIT target for early exits from RUN-ELIGIBILITY-CHECK.

7. Constraints

7.1 Input Constraints

  • The Application ID must be non-zero for both F1 and F3.
  • Checked-By must not be spaces for F1.
  • The application must exist and load successfully (DECMSG = 'APPLICATION LOADED') before the rules run.

7.2 License Type and Age Constraints

  • Only L, P and O are recognised. Any other value skips the age check and sets no failure flag.
  • Age is a simple year difference, not an exact date comparison.

7.3 CICS Constraints

  • The COMMAREA is fixed at 350 bytes. This matches DFHCOMMAREA PIC X(350).
  • Only F1, F3 and F12 are accepted. Any other key produces USE F1 F3 OR F12.
  • On first entry (EIBCALEN = 0) the program only displays the blank screen.

8. Error Handling

Condition Handling Message
Application ID is zero (F3) Branch to LOAD-APPLICATION-EXIT, no SQL ENTER APPLICATION ID
Application ID is zero (F1) GO TO RUN-ELIG-EXIT ENTER APPLICATION ID FIRST
Checked-By is blank GO TO RUN-ELIG-EXIT, no update CHECKED-BY IS REQUIRED
SQLCODE = 100 on lookup Branch to LOAD-APPLICATION-EXIT APPLICATION NOT FOUND
Load did not return success GO TO RUN-ELIG-EXIT The load message is shown
Unrecognised key No processing USE F1 F3 OR F12
Business rule failure WS-FAIL-FLAG = Y, result recorded as failed The failure reason

8.1 Known Limitations

  • Negative SQLCODE values (hard SQL errors) are not checked on the SELECT, the COUNT(*) queries or the UPDATE.
  • RESP(WS-RESP1) is captured on SEND MAP and RECEIVE MAP, but it is never tested. CICS map I/O errors are therefore silently ignored.

9. Examples

9.1 Example 1: Successful Learner Eligibility Check

Input. Application ID 1001 and Checked-By OFFICER01. The user presses F1 on 2024-05-15. The candidate is Alice Smith, born 2007-03-12, and the license type is L.

Processing. The age is 2024 − 2007 = 17, which is at least 16. A Learner license has no prerequisite, so the fail flag stays N.

Result.

9.2 Example 2: Failed Probation Check, Missing Learner License

Input. Application ID 1002 and Checked-By OFFICER02. The user presses F1 on 2024-05-15. The candidate is Bob Brown, born 2005-08-20, and the license type is P. There is no active Learner license in ISSUED_LICENSE for candidate 502.

Processing. The age is 2024 − 2005 = 19, which meets the minimum of 17. The prerequisite count is 0, so the check fails.

Result.

Item Value
DECCNAMO BOB BROWN
DECMAGEO / DECAGEO 17 / 19
DECESTSO FAIL
DECENTSO and DECMSG MUST HOLD ACTIVE LEARNER LICENSE FOR PROBATION
ELIG_CHECK_STATUS F
APPLICATION_STATUS RE
LAST_UPDATED_BY OFFICER02

10. Business Significance

  • Age enforcement. The age rules keep under-age applicants from advancing to licenses they are not legally entitled to hold. The year-based calculation is approximate, so it could let through a candidate who is just short of the minimum age.
  • Graduated licensing. The prerequisite rule enforces the Learner → Probation → Open progression. Without it, applicants could skip intermediate stages.
  • Reliable workflow state. Always writing EC or RE leaves the application in a defined state. Downstream steps can act on that state.
  • Auditability. The date, the officer ID and the failure notes are stored on the application record.
