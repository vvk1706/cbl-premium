CICS Integration Patterns

1. Overview

The Driver License Information System (DLIS) is a set of CICS/COBOL online transactions. Operators use 3270 terminals to register candidates, enter license applications, take fee payments and issue licenses. The programs share a small set of CICS design patterns:

Pattern Purpose Main programs
Pseudo-conversational processing The task ends after every screen interaction and is re-queued under the same transaction ID. No task or storage is held while the operator thinks. All DLIS programs
BMS maps One map per program, sent with ERASE on first display and DATAONLY afterwards. Function keys (AID) select the action. All DLIS programs
COMMAREA context passing A fixed 350-byte DLIS-COMMAREA carries session context between invocations and between programs. All DLIS programs
XCTL control transfer The main menu hands control to a functional program and is released from storage. DLISMENU to nine downstream programs
LINK and print delegation A functional program calls a print program as a subroutine and then regains control. DLISPAY to DLISRPRT; DLISISSU to DLISLPRT

This page describes how these patterns work together at application level. It uses the menu program DLISMENU and the functional programs DLISCAND, DLISAPPL, DLISPAY and DLISISSU as examples.

3. Pseudo-Conversational Processing

3.1 Principle

Every DLIS program ends its task after each screen interaction. It issues EXEC CICS RETURN TRANSID(...) COMMAREA(...). CICS then re-invokes the same transaction when the operator presses an attention key. From the operator’s point of view the screen stays up and waits. Meanwhile the system holds no running task for that terminal.

All DLIS programs have the same top-level structure:

Paragraph Responsibility
MAIN-LOGIC Tests EIBCALEN to decide between first entry and re-entry.
INIT-SCREEN First entry only. Sets the date, sends the map with ERASE FREEKB, and returns with the transaction ID.
PROCESS-INPUT Re-entry. Receives the map, dispatches on EIBAID, re-sends the map with DATAONLY FREEKB, and returns with the transaction ID.

3.4 Code Pattern: Entry Dispatch

COBOL 
MAIN-LOGIC.
           IF EIBCALEN = 0
               PERFORM INIT-SCREEN
           ELSE
               MOVE DFHCOMMAREA TO DLIS-COMMAREA
               PERFORM PROCESS-INPUT
           END-IF.
           STOP RUN.

DLISCAND, DLISAPPL and DLISPAY also move EIBTRNID into CA-TRANSACTION-ID at entry.

3.5 Code Pattern: First Display

COBOL 
INIT-SCREEN.
           MOVE CURRENT-DATE(1:10) TO DPEDATE
           EXEC CICS SEND MAP('DLISPE01') MAPSET('DLISPE')
                ERASE FREEKB RESP(WS-RESP1)
           END-EXEC
           EXEC CICS RETURN TRANSID('DL07')
                COMMAREA(DLIS-COMMAREA) LENGTH(350)
           END-EXEC.

This snippet is from DLISPAY. The other programs follow the same shape with their own map names, mapsets, date fields and transaction IDs.

3.6 Behavior Rules

  • Every re-entry must arrive under the same transaction ID with a 350-byte COMMAREA. Otherwise EIBCALEN is zero and the screen is re-initialised, which discards in-flight state.
  • Every path through the main logic ends in EXEC CICS RETURN. The STOP RUN after the PERFORM statements is effectively unreachable.
  • PF12 is the exit key in every program. It issues EXEC CICS RETURN with no TRANSID, which ends the conversation.
  • A validation error does not loop inside the task. The program sets a message and still goes through a full SEND MAP / RETURN TRANSID cycle.

4.3 RECEIVE MAP and AID Dispatch

RECEIVE MAP always runs before the AID is evaluated. The function key then selects the action.

COBOL 
PROCESS-INPUT.
           EXEC CICS RECEIVE MAP('DLISPE01') MAPSET('DLISPE')
                RESP(WS-RESP1)
           END-EXEC
           EVALUATE TRUE
               WHEN EIBAID = DFHPF1
                   PERFORM PROCESS-PAYMENT
               WHEN EIBAID = DFHPF3
                   PERFORM LOAD-APPLICATION
               WHEN EIBAID = DFHPF5
                   PERFORM PRINT-RECEIPT
               WHEN EIBAID = DFHPF12
                   EXEC CICS RETURN END-EXEC
               WHEN OTHER
                   MOVE 'USE F1 F3 F5 OR F12' TO DPEMSG
           END-EVALUATE.

The program sources show the final branch of this dispatch as OTHER rather than WHEN OTHER. Valid COBOL requires WHEN OTHER. The snippet above shows the intended, valid form.

4.5 Single Message Field Pattern

Each map has one message field: DMMMSG, DCMMSG, DAEMSG, DPEMSG or DLIMSG. It carries every validation error, business-rule rejection, database error and success confirmation. The program sets the text and then sends the map.

A called paragraph can also use the message as a status result. DLISPAY and DLISISSU run LOAD-APPLICATION first, then continue only if the message is APPLICATION LOADED. The comparison depends on the exact text of the message, so changing the wording would break the check.

5. COMMAREA Context Passing

5.1 Structure

The shared DLIS-COMMAREA is defined in the DLISCSEC copybook. The Linkage Section receives it as DFHCOMMAREA PIC X(350).

Field Content
CA-TRANSACTION-ID 4-character transaction ID of the originating or returning transaction
CA-RETURN-SCREEN 8-character program name to return to after navigation
CA-CANDIDATE-ID Candidate in context (packed decimal)
CA-APPLICATION-ID Application in context (packed decimal)
CA-LICENSE-ID Issued license in context (packed decimal)
CA-PAYMENT-ID Payment in context (packed decimal)
CA-USER-ID 8-character operator ID
CA-RETURN-CODE Result code from a previous program
CA-MSG-TEXT 78-character message passed back for display
CA-MSG-COLOR 5-character message color
CA-ACTION Single-character action code

DLISCSEC also defines DLIS-CAND-COMMAREA, DLIS-APPL-COMMAREA and WS-CICS-RESPONSE. WS-CICS-RESPONSE holds WS-RESP1, WS-RESP2 and the EIB save fields.

5.2 Context Flow

graph LR subgraph Cycle[Pseudo-conversational cycle] R1[RETURN TRANSID
COMMAREA LENGTH 350] --> CICS1[CICS holds COMMAREA] CICS1 --> D[DFHCOMMAREA
PIC X 350] D --> W[DLIS-COMMAREA
working storage] W --> R1 end W -- XCTL COMMAREA --> N[Next program] W -- LINK COMMAREA --> PR[Print program] PR -. updated COMMAREA .-> W

The COMMAREA moves along three paths:

  1. Same program, next interaction. RETURN TRANSID(...) COMMAREA(...) stores it, and the next invocation receives it as DFHCOMMAREA.
  2. Forward transfer. XCTL passes it to the next program. The caller does not regain control.
  3. Subroutine call. LINK passes it to a print program and then regains control.

5.3 Code Pattern: Restore and Return

COBOL 
LINKAGE SECTION.
       01  DFHCOMMAREA              PIC X(350).

           ...
           MOVE DFHCOMMAREA TO DLIS-COMMAREA

           ...
           EXEC CICS RETURN TRANSID('DL01')
                COMMAREA(DLIS-COMMAREA) LENGTH(350)
           END-EXEC.

5.4 Data Handed to Downstream Programs

Field Used by
CA-PAYMENT-ID Relays the new payment ID to the receipt print program
CA-APPLICATION-ID Available to the print programs
CA-CANDIDATE-ID Candidate context across screens
CA-USER-ID Operator identity and audit continuity
CA-MSG-TEXT, CA-MSG-COLOR Messages from a previous program for display on the menu

5.5 Constraints

  • The length is fixed at 350 bytes in every RETURN, XCTL and LINK. The menu hard-codes it in all three RETURN calls and all ten XCTL calls. Every receiving program must expect exactly this layout.
  • DLIS-COMMAREA is shorter than 350 bytes. The DLISISSU documentation puts it at roughly 130 bytes. The declared length is larger than the data structure, and no program checks that the two match.
  • A message in the COMMAREA is limited to 78 characters, and CA-USER-ID to 8 characters.
  • The programs test only for a zero EIBCALEN. They do not validate the length or content of the COMMAREA beyond that.
  • The menu does not set anything in the COMMAREA to distinguish option 1 from option 2, so DLISCAND cannot tell them apart.

6.3 Code Pattern: Menu Validation and Routing

COBOL 
PROCESS-INPUT.
           EXEC CICS RECEIVE MAP('DLISMM01') MAPSET('DLISMM')
                RESP(WS-RESP1)
           END-EXEC
           IF EIBAID = DFHPF12
               EXEC CICS RETURN END-EXEC
           END-IF
           IF EIBAID NOT = DFHENTER
               MOVE 'PRESS ENTER TO SELECT OR F12 TO EXIT' TO DMMMSG
               PERFORM REDISPLAY-MENU
           END-IF
           IF DMMOPTI = SPACES OR LOW-VALUES
               MOVE 'PLEASE SELECT AN OPTION (1-10)' TO DMMMSG
               PERFORM REDISPLAY-MENU
           END-IF
           EVALUATE DMMOPTI
               WHEN '3'
                   EXEC CICS XCTL PROGRAM('DLISAPPL')
                        COMMAREA(DLIS-COMMAREA) LENGTH(350)
                   END-EXEC
               ...
               WHEN OTHER
                   MOVE 'INVALID OPTION. PLEASE SELECT 1-10' TO DMMMSG
                   PERFORM REDISPLAY-MENU
           END-EVALUATE.

Only the WHEN '3' branch is written out here. The other nine follow the same shape. The two validation IF blocks work because REDISPLAY-MENU ends in a CICS RETURN, so later statements are not reached.

6.4 Error Redisplay in the Menu

COBOL 
REDISPLAY-MENU.
           EXEC CICS SEND MAP('DLISMM01') MAPSET('DLISMM')
                DATAONLY FREEKB RESP(WS-RESP1)
           END-EXEC
           EXEC CICS RETURN TRANSID('DL01')
                COMMAREA(DLIS-COMMAREA) LENGTH(350)
           END-EXEC.

REDISPLAY-MENU does not set a message. The caller sets DMMMSG first.

6.5 XCTL Behavior

  • One way. XCTL releases DLISMENU and control never returns to it. All state the target needs must travel in the 350-byte COMMAREA.
  • Same logical level. There is no stack of callers, unlike LINK.
  • Fixed contract. Every XCTL uses COMMAREA(DLIS-COMMAREA) LENGTH(350).
  • No error handling. None of the XCTL calls has a RESP option or a HANDLE CONDITION. If a target program is missing or disabled, CICS applies its default behavior and abends the task.
  • Return to the menu. After an XCTL, the target program runs under its own transaction ID. The functional programs in this document end with RETURN TRANSID for their own transaction and do not transfer back to DL01. They do not use CA-RETURN-SCREEN to navigate elsewhere. Operators return to the menu by starting DL01 again.

7. Print Program Delegation with LINK

7.1 Pattern

Two functional programs delegate printing to separate programs by using EXEC CICS LINK. This is a subroutine call. The called program runs at a lower logical level and control comes back to the caller. The caller keeps its screen and its place in the pseudo-conversation.

Caller Key Print program Condition for printing
DLISPAY (DL07) PF5 DLISRPRT Receipt number field DPERCTO is not blank
DLISISSU (DL10) PF6 DLISLPRT License number field DLIILNUMO is not blank

7.2 Code Pattern

COBOL 
PRINT-RECEIPT.
           IF DPERCTO = SPACES
               MOVE 'PROCESS PAYMENT FIRST BEFORE PRINTING' TO DPEMSG
               GO TO PRINT-RECEIPT-EXIT
           END-IF
           EXEC CICS LINK PROGRAM('DLISRPRT')
                COMMAREA(DLIS-COMMAREA) LENGTH(350)
           END-EXEC
           MOVE 'RECEIPT SENT TO PRINTER' TO DPEMSG.
       PRINT-RECEIPT-EXIT.
           EXIT.

DLISISSU uses the same shape for PRINT-LICENSE. It guards on DLIILNUMO, links to DLISLPRT, and sets LICENSE SENT TO PRINTER.

7.3 Sequence: Payment, Then Receipt Print

sequenceDiagram participant Op as Operator participant Pay as DLISPAY DL07 participant DB as DB2 participant Prt as DLISRPRT Op->>Pay: F3 with application ID Pay->>DB: Read application, candidate, fee Pay-->>Op: Application loaded Op->>Pay: F1 with method and reference Pay->>DB: INSERT PAYMENT, UPDATE LICENSE_APPLICATION Pay-->>Op: Receipt number and payment ID shown Op->>Pay: F5 Pay->>Pay: Check receipt number is present Pay->>Prt: LINK COMMAREA 350 with CA-PAYMENT-ID Prt-->>Pay: Return to caller Pay-->>Op: Message RECEIPT SENT TO PRINTER

7.4 Design Points

  • Guard before delegation. Both callers refuse to print until the business action has happened, which is a payment in DLISPAY and an issued license in DLISISSU. The guard tests the screen output field, not a database value.
  • Context through the COMMAREA. DLISPAY relays the new payment ID in CA-PAYMENT-ID, so DLISRPRT can retrieve and format the right receipt. DLISISSU passes DLIS-COMMAREA so DLISLPRT can locate the issued license. DLISISSU does not copy the generated license number into the COMMAREA.
  • Required size. Each print program must accept a 350-byte COMMAREA.
  • Resource definitions. The print programs must be defined in CICS group DLISGRP and available in DLIS.LOADLIB.
  • No outcome check. The LINK has no RESP or HANDLE CONDITION. The success message is shown whether or not printing worked. If the program is not found or abends, CICS applies default handling and normally abends the task.

8. Error Handling Patterns

The programs use the same error-handling approach, with the same gaps.

8.1 Fail-Fast Guards with Exit Paragraphs

Business paragraphs check conditions in order and branch to a dedicated exit paragraph on the first failure. The names are LOAD-APP-EXIT, PROCESS-PAY-EXIT, ISSUE-LIC-EXIT, CREATE-CANDIDATE-EXIT, LOOKUP-CANDIDATE-EXIT and similar. Only the first failing message is shown, and no database work happens after a failed check.

COBOL 
IF DPEMETHI = SPACES
               MOVE 'PAYMENT METHOD IS REQUIRED' TO DPEMSG
               GO TO PROCESS-PAY-EXIT
           END-IF
           IF DPEMETHI NOT = 'CC' AND 'DC' AND 'EF' AND 'CS' AND 'CH'
               MOVE 'INVALID PAYMENT METHOD' TO DPEMSG
               GO TO PROCESS-PAY-EXIT
           END-IF

8.2 Error Handling Summary

Area Behavior
AID keys Unknown keys produce a hint message and a redisplay. PF12 exits cleanly.
Input validation Required-field and domain checks run before any SQL. Each failure shows a message on the map and keeps the conversation going.
DB2 SQLCODE is checked inconsistently: 100 after most SELECT statements, and non-zero after most INSERT and UPDATE statements. Checks after the identity retrieval and some updates are missing.
CICS SEND / RECEIVE RESP(WS-RESP1) is coded, which suppresses the default abend, but the value is never tested. A MAPFAIL passes silently.
XCTL / LINK No RESP, no HANDLE CONDITION, no HANDLE ABEND. CICS defaults apply.
Unit of work No explicit SYNCPOINT or ROLLBACK. Commit happens at task end through RETURN.
Diagnostics No logging to TD or TS queues. The common return code and message fields in DLISWS are defined but unused.

8.3 Known Gaps

  • Because RESP(WS-RESP1) is never tested, a failed RECEIVE MAP lets the program carry on with stale or empty map data.
  • In DLISPAY and DLISISSU, the UPDATE of LICENSE_APPLICATION is not checked after the INSERT. The success message can appear even if the update failed.
  • Some bare OTHER branches in EVALUATE statements in DLISMENU, DLISCAND, DLISAPPL and DLISISSU are written without WHEN and need correcting.
  • Option 10 on the menu compares against '10', which may not fit the one-character option field. It could be unreachable, depending on the map definition.

9. Build and Runtime Dependencies

Area Detail
CICS resources Programs, transactions and mapsets are defined in csd/DLISCSD.csd (group DLISGRP), installed with DFHCSDUP.
BMS jcl/DLISBMS.jcl with proc/DLISBASM.proc assembles the maps into DLIS.LOADLIB. Symbolic maps are generated into DLIS.COPYBOOK.
Compile and link jcl/DLISCOMP.jcl with proc/DLISCLNK.proc. The DB2 precompiler DSNHPC runs first. The compiler IGYCRCTL uses RENT,APOST,LIB,NOSEQ,NOTERM. The link editor IEWL uses AMODE(31),RMODE(ANY).
DB2 Subsystem DSN1, plan DLISPLAN, collection DLISPKG. Bound by jcl/DLISBIND.jcl.
Copybooks DLISWS (shared working storage and SQLCA), DLISCSEC (COMMAREA layouts), DLISDCLG (DCLGEN host structures). DFHAID supplies the attention-key constants.

DLISMENU includes SQLCA through DLISWS but runs no SQL. The DB2 precompiler still processes it at compile time.

10. Summary of Integration Patterns

graph TD OP[Operator] --> MENU[DLISMENU DL01
pseudo-conversational hub] MENU -- XCTL + COMMAREA --> FUNC[Functional programs
each pseudo-conversational] FUNC -- BMS map plus AID keys --> OP FUNC -- RETURN TRANSID + COMMAREA --> FUNC FUNC -- LINK + COMMAREA --> PRINT[Print programs
DLISRPRT DLISLPRT] FUNC -- EXEC SQL --> DB2[(DB2 DLIS)]
Pattern Key rule
Pseudo-conversational Test EIBCALEN. Always end with RETURN TRANSID(...) COMMAREA(...) LENGTH(350). Use PF12 as the only clean exit.
BMS ERASE FREEKB on first send, DATAONLY FREEKB on later sends. One message field per map.
COMMAREA A fixed 350-byte DLIS-COMMAREA. Restore it from DFHCOMMAREA on every re-entry.
XCTL The menu hands over the whole COMMAREA and is released. There is no return path.
LINK The caller guards on a screen value, calls the print program with the COMMAREA, then reports the result.

New DLIS programs should follow the same skeleton: MAIN-LOGIC with an EIBCALEN test, INIT-SCREEN, PROCESS-INPUT, fail-fast business paragraphs with exit paragraphs, and the shared COMMAREA contract. They should also test RESP values and add RESP handling on XCTL and LINK, which the current programs omit.
