License Issuance (DL10)

1. Overview

DLISISSU is a CICS pseudo-conversational COBOL program that implements the driver license issuance function within the DLIS (Driver Licensing Information System) application suite. It runs under CICS transaction identifier DL10 and presents a single interactive screen — BMS map DLISLIM01 within mapset DLISLI — through which a licensing officer manages the full issuance lifecycle.

The officer loads an approved license application by its ID and reviews the applicant’s name, license type, and the status of five prerequisite checks: eligibility, driving history, payment, and two levels of approval. Once satisfied, the officer enters the vehicle class, their own identifier, the issuing authority, and any applicable restrictions. The program then:

  • Confirms the application has reached Approved (AP) status.
  • Calculates the license validity period and expiry date based on the license type.
  • Generates a structured license number encoding the type, vehicle class, candidate, and application.
  • Inserts the new license record into DLIS.ISSUED_LICENSE.
  • Updates the application status to Issued (IS) in DLIS.LICENSE_APPLICATION.
  • Optionally delegates printing to the external program DLISLPRT.

All state between screen interactions is carried in a 350-byte CICS COMMAREA (DLIS-COMMAREA), following the standard pseudo-conversational pattern: no CICS task exists between keystrokes, and the program is re-invoked with each operator attention key.

The program sits at the center of the architecture: it receives operator input through BMS, reads and writes relational data through DB2, preserves session state through the CICS COMMAREA, and delegates physical license production to DLISLPRT via a synchronous CICS LINK.

3. Processing Logic

3.1 Pseudo-Conversational Execution Model

DLISISSU follows the standard CICS pseudo-conversational pattern. When EIBCALEN equals zero, no COMMAREA was passed — this is the very first invocation — and the program routes to INIT-SCREEN. On every subsequent invocation, EIBCALEN is non-zero, DFHCOMMAREA is moved into DLIS-COMMAREA, and control passes to PROCESS-INPUT.

After each processing cycle, the program issues:

COBOL 
EXEC CICS RETURN TRANSID('DL10') COMMAREA(DLIS-COMMAREA) LENGTH(350)
END-EXEC

This suspends the task, returns the terminal to the user, and pre-arms CICS to re-invoke DLISISSU under transaction DL10 on the next attention key. No z/OS storage is held between keystrokes — the full 350-byte session state lives exclusively in the CICS-managed COMMAREA.

3.3 Function Key Dispatch

Only four attention keys are accepted. They are tested with EVALUATE TRUE on EIBAID against DFHAID copy-library constants:

Key DFHAID Constant Action
F1 DFHPF1 PERFORM ISSUE-LICENSE — issue the license
F3 DFHPF3 PERFORM LOAD-APPLICATION — load and display an application
F6 DFHPF6 PERFORM PRINT-LICENSE — delegate to DLISLPRT
F12 DFHPF12 EXEC CICS RETURN — terminate the transaction cleanly
Any other OTHER Display 'USE F1 F3 F6 OR F12'; no business action
COBOL 
EVALUATE TRUE
    WHEN EIBAID = DFHPF1   PERFORM ISSUE-LICENSE
    WHEN EIBAID = DFHPF3   PERFORM LOAD-APPLICATION
    WHEN EIBAID = DFHPF6   PERFORM PRINT-LICENSE
    WHEN EIBAID = DFHPF12  EXEC CICS RETURN END-EXEC
    OTHER
        MOVE 'USE F1 F3 F6 OR F12' TO DLIMSG
END-EVALUATE

4. Load Application (F3)

4.1 Purpose

The LOAD-APPLICATION paragraph retrieves a license application and its associated candidate record from DB2, then displays all five prerequisite gate statuses on the screen so the officer can assess readiness for issuance. A successful load also sets the message 'APPLICATION LOADED', which the ISSUE-LICENSE paragraph uses as its own internal gate condition.

4.2 Load Application Flow

4.3 Application ID Validation

Before any DB2 access, the Application ID field is verified:

COBOL 
IF DLIAIDI = ZEROS
    MOVE 'ENTER APPLICATION ID' TO DLIMSG
    GO TO LOAD-APP-EXIT
END-IF

4.4 DB2 JOIN Query

The SELECT joins DLIS.LICENSE_APPLICATION with DLIS.CANDIDATE on CANDIDATE_ID, retrieving all fields needed for display and downstream issuance:

  • From DLIS.LICENSE_APPLICATION: CANDIDATE_ID, LICENSE_TYPE, APPLICATION_STATUS, ELIG_CHECK_STATUS, HIST_CHECK_STATUS, PAYMENT_STATUS, APPROVAL_1_STATUS, APPROVAL_2_STATUS
  • From DLIS.CANDIDATE: FIRST_NAME, LAST_NAME

5. Issue License (F1)

5.1 Purpose

ISSUE-LICENSE is the primary business logic paragraph. It performs all input validation, reloads the application from DB2, enforces the approved-status gate, derives the expiry date and license number, inserts the license record, and updates the application status to Issued.

5.3 Input Validation (Four Sequential Guards)

Validation is fail-fast — only the first failing rule is reported, and processing exits immediately via GO TO ISSUE-LIC-EXIT:

    GO TO ISSUE-LIC-EXIT

    MOVE 'VEHICLE CLASS MUST BE A B C OR D' TO DLIMSG

    MOVE 'ISSUING OFFICER IS REQUIRED' TO DLIMSG
    GO TO ISSUE-LIC-EXIT
END-IF

5.4 Application Status Gate

After successfully reloading the application via PERFORM LOAD-APPLICATION, the composite status is checked:

COBOL 
*    All five gates must be fully satisfied
IF APPLICATION-STATUS OF DCLDLIS-LICENSE-APPL NOT = 'AP'
    MOVE 'APPLICATION STATUS MUST BE AP BEFORE ISSUE'
        TO DLIMSG
    GO TO ISSUE-LIC-EXIT
END-IF

Business Significance: This is the single programmatic gate. The five individual prerequisite statuses (eligibility, history, payment, approval 1, approval 2) are displayed for the officer’s visual review but are not individually tested in code — they are assumed to be reflected by the composite 'AP' status. Once a license is issued and the status transitions to 'IS', any subsequent F1 attempt will fail this gate, preventing duplicate issuance.

5.5 Expiry Date Calculation and License Prefix Assignment

The validity period and license number prefix are determined by license type:

COBOL 
MOVE CURRENT-DATE(1:10) TO WS-ISSUE-DATE
MOVE CURRENT-DATE(1:4)  TO WS-EXPIRY-YYYY
MOVE CURRENT-DATE(5:6)  TO WS-EXPIRY-MMDD
EVALUATE LICENSE-TYPE OF DCLDLIS-LICENSE-APPL
    WHEN 'L'
        ADD 1 TO WS-EXPIRY-YYYY
        MOVE 'LRN' TO WS-LIC-PREFIX
    WHEN 'P'
        ADD 2 TO WS-EXPIRY-YYYY
        MOVE 'PRB' TO WS-LIC-PREFIX
    WHEN 'O'
        ADD 5 TO WS-EXPIRY-YYYY
        MOVE 'OPN' TO WS-LIC-PREFIX
END-EVALUATE
STRING WS-EXPIRY-YYYY WS-EXPIRY-MMDD
    INTO WS-EXPIRY-DATE
License Type Description Years Added Prefix
L Learner +1 year LRN
P Probationary +2 years PRB
O Open/Full +5 years OPN

Note: There is no WHEN OTHER clause. An unrecognised license type leaves WS-LIC-PREFIX uninitialized and the expiry year unchanged (same year as issue), without any error or abend. The expiry date is assembled by combining the computed year with the current month and day, so the license always expires on the same calendar date as issue, in a future year.

5.6 License Number Generation

The license number is built by concatenating four components without delimiters:

COBOL 
*    Generate license number
STRING WS-LIC-PREFIX DLIVCLSI
       CANDIDATE-ID OF DCLDLIS-LICENSE-APPL
       APPLICATION-ID OF DCLDLIS-LICENSE-APPL
    INTO WS-LICENSE-NUMBER
Component Source Example
Type prefix Derived from license type PRB
Vehicle class Operator input DLIVCLSI B
Candidate ID DCLDLIS-LICENSE-APPL.CANDIDATE-ID (COMP-3) raw packed bytes
Application ID DCLDLIS-LICENSE-APPL.APPLICATION-ID (COMP-3) raw packed bytes

Note: CANDIDATE-ID and APPLICATION-ID are PIC S9(10) COMP-3 (packed decimal) fields. Their raw internal representation is concatenated into the 20-character WS-LICENSE-NUMBER without conversion to display format, meaning the license number will contain non-printable bytes from those packed fields.

If SQLCODE NOT = 0, the message 'DATABASE ERROR ON LICENSE INSERT' is set and the paragraph exits via GO TO ISSUE-LIC-EXIT. The application status UPDATE is skipped.

5.7.2 UPDATE DLIS.LICENSE_APPLICATION

COBOL 
*    Update application to IS=Issued
EXEC SQL
    UPDATE DLIS.LICENSE_APPLICATION SET
        APPLICATION_STATUS = 'IS',
        LAST_UPDATED_DATE  = CURRENT DATE,
        LAST_UPDATED_BY    = :DLIOFCRI
    WHERE APPLICATION_ID   = :APPLICATION-ID
                             OF DCLDLIS-LICENSE-APPL
END-EXEC

Important: The SQLCODE from this UPDATE is not checked. If it fails silently, the license INSERT stands but the application status remains 'AP', creating a potential data inconsistency. There is no explicit SYNCPOINT or ROLLBACK; the INSERT and UPDATE are committed together as one unit of work when the task returns to CICS at task end.

5.8 Successful Issuance Output

On success, the generated license number and expiry date are presented on screen:

COBOL 
MOVE WS-LICENSE-NUMBER TO DLIILNUMO
MOVE WS-EXPIRY-DATE    TO DLIEXPO
MOVE 'DRIVER LICENSE ISSUED SUCCESSFULLY' TO DLIMSG.

6. Print License (F6)

6.1 Purpose

The PRINT-LICENSE paragraph delegates physical license production to the external program DLISLPRT. It enforces that a license must have been successfully issued in the current session before printing is allowed.

6.2 Print License Flow

sequenceDiagram participant Officer as Licensing Officer participant DLISISSU as DLISISSU (PRINT-LICENSE) participant DLISLPRT as DLISLPRT Officer->>DLISISSU: Press F6 DLISISSU->>DLISISSU: Check DLIILNUMO ≠ SPACES alt No license number on screen DLISISSU-->>Officer: DLIMSG = "ISSUE LICENSE FIRST BEFORE PRINTING" else License number present DLISISSU->>DLISLPRT: EXEC CICS LINK PROGRAM('DLISLPRT')\nCOMMARE(DLIS-COMMAREA) LENGTH(350) DLISLPRT-->>DLISISSU: Return (synchronous) DLISISSU-->>Officer: DLIMSG = "LICENSE SENT TO PRINTER" end

6.3 Print Guard and Invocation

COBOL 
IF DLIILNUMO = SPACES
    MOVE 'ISSUE LICENSE FIRST BEFORE PRINTING' TO DLIMSG
    GO TO PRINT-LIC-EXIT
END-IF
EXEC CICS LINK PROGRAM('DLISLPRT')
    COMMAREA(DLIS-COMMAREA) LENGTH(350)
END-EXEC
MOVE 'LICENSE SENT TO PRINTER' TO DLIMSG.

The EXEC CICS LINK is a synchronous call: DLISISSU suspends at the LINK point, DLISLPRT runs to completion and returns, then control resumes at the next statement. The entire 350-byte DLIS-COMMAREA is forwarded, giving DLISLPRT access to all context fields including CA-APPLICATION-ID, CA-CANDIDATE-ID, and CA-LICENSE-ID.

Note: The LINK command does not specify a RESP option. If the link fails (e.g., program not found), CICS raises a default abend rather than allowing graceful in-program recovery.

9. Error Handling

9.1 Input Validation Errors

All input validation errors follow the same pattern: set DLIMSG to a descriptive text and branch to the exit paragraph via GO TO, bypassing all remaining processing. Only the first failing validation is reported per interaction (fail-fast).

9.2 Database Error Handling

Scenario Detection Response
Application not found SQLCODE = 100 after SELECT DLIMSG = 'APPLICATION NOT FOUND'
INSERT failure SQLCODE NOT = 0 after INSERT DLIMSG = 'DATABASE ERROR ON LICENSE INSERT'; UPDATE is skipped
UPDATE failure Not checked Success message is shown regardless; potential data inconsistency
Other SELECT errors Not checked Falls through as if the application were loaded

11. Business Rules Summary

11.1 Issuance Pre-conditions

All of the following must be satisfied before a license record is created:

  1. An Application ID must be provided.
  2. The vehicle class must be one of A, B, C, or D.
  3. An issuing officer identifier must be provided.
  4. An issuing authority identifier must be provided.
  5. The application must exist in the database (SQLCODE ≠ 100).
  6. APPLICATION_STATUS must equal 'AP' (Approved).

11.2 Fixed Values on Every Issued License

Attribute Fixed Value Meaning
LICENSE_STATUS 'A' Active
DEMERIT_BALANCE 12 Full starting demerit allowance
ISSUE_DATE CURRENT DATE DB2 server date at execution time

11.3 Re-Issuance Prevention

After successful issuance, the application status transitions from 'AP' to 'IS'. Any subsequent F1 attempt for the same application will fail the status gate (APPLICATION_STATUS NOT = 'AP'), preventing duplicate license issuance.

12. Operational Examples

12.1 Example 1 — Successful License Issuance (F1)

Input:

Field Value
Application ID (DLIAIDI) 1001
Vehicle class (DLIVCLSI) B
Issuing officer (DLIOFCRI) OFFICER01
Issuing authority (DLIAUTHI) DMV-CENTRAL
Restrictions (DLIRSTI) CORRECTIVE LENSES

Database state: LICENSE_TYPE = 'P', APPLICATION_STATUS = 'AP', candidate John Smith. Current date: 2025-03-15.

Expected outcome:

  • Message: DRIVER LICENSE ISSUED SUCCESSFULLY
  • Expiry date (DLIEXPO): 2027-03-15 (P-type: +2 years)
  • License number (DLIILNUMO): begins PRBB followed by packed-decimal bytes of candidate and application IDs
  • New row in DLIS.ISSUED_LICENSE with LICENSE_STATUS = 'A', DEMERIT_BALANCE = 12
  • DLIS.LICENSE_APPLICATION updated: APPLICATION_STATUS = 'IS', LAST_UPDATED_BY = 'OFFICER01'

12.2 Example 2 — Application Not Yet Approved (F1)

Database state for application 1002: APPLICATION_STATUS = 'PN' (pending).

Expected outcome:

  • Message: APPLICATION STATUS MUST BE AP BEFORE ISSUE
  • No INSERT or UPDATE performed.

12.3 Example 3 — Invalid Vehicle Class (F1)

Input: Vehicle class = X.

Expected outcome:

  • Message: VEHICLE CLASS MUST BE A B C OR D
  • No database access occurs; fail-fast validation stops at the second guard.

12.4 Example 4 — Load Application (F3)

Input: Application ID 1001.

Expected outcome:

  • DLICNAMO: JOHN SMITH
  • DLILTYO: P
  • All five gate status fields populated from the database
  • Message: APPLICATION LOADED

12.5 Example 5 — Print and Navigation Keys

Action Result
F6 before issuance (license number blank) ISSUE LICENSE FIRST BEFORE PRINTING
F6 after successful issuance CICS LINK to DLISLPRT → LICENSE SENT TO PRINTER
F12 Transaction ends cleanly (bare EXEC CICS RETURN)
Any other key (e.g. Enter, PF2) USE F1 F3 F6 OR F12
First invocation (EIBCALEN = 0) Blank DLISLIM01 map sent; transaction re-queued as DL10
