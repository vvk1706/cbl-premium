Driver License Information System (DLIS) – CICS/COBOL Knowledge Base

Architecture and functional documentation for the DLIS CICS/COBOL application. It covers the full driver license workflow: candidate maintenance, application entry, eligibility and history checks, payment, two-level authority approval and license issuance. The application runs on DB2 and is reached through a central menu.

Application Documentation
Overview
DLIS System Overview High-level introduction to the Driver License Information System: purpose, the set of CICS transactions (DL01–DL10), the programs behind them and how they support the end-to-end licensing process. Main Menu & Navigation (DL01) The pseudo-conversational main menu program DLISMENU. It covers the BMS map, option routing to the ten downstream transactions, and how session context is passed through the shared communication area using XCTL.
Candidate & Application Intake
Candidate Maintenance (DL02) DLISCAND: creating, updating, inquiring on and deactivating candidate records through function keys on a single 3270 screen, including validation of required fields and duplicate national ID checks. License Application Entry (DL03) DLISAPPL: how clerks look up a candidate, retrieve the initial-issue fee for a license type (Learner, Probation, Open) and submit a new pending license application, with duplicate open-application checks. Application Status Inquiry (DL04) DLISSTAT: read-only inquiry that displays each workflow stage of an application (eligibility, history, payment, two approvals), the overall status description and issued license details.
Verification & Payment
Eligibility Check (DL05) DLISELIG: evaluates whether a candidate qualifies for the requested license type based on minimum age and prerequisite active license, and records the result, failure reason, officer and resulting application status. Driving History Check (DL06) DLISHIST: retrieval and scrollable display of a candidate's active driving incidents and the pass/fail decision based on suspensions, demerit points and unpaid fines, gated by a passed eligibility check. Payment Entry & Processing (DL07) DLISPAY: fee lookup, payment recording in the PAYMENT table, receipt number generation, application status update to paid, and receipt printing delegated to DLISRPRT via EXEC CICS LINK.
Approval & License Issuance
First-Level Authority Approval (DL08) DLISAP1: authority user validation, level-1 approval rights and license type authorization, and the approve/reject decision that moves an application to second-level review (A2) or closes it (RE). Second-Level Authority Approval (DL09) DLISAP2: final approval step with level-2 authority validation, segregation of duties against the first approver, license type authorization, and the decision that sets status AP (approved) or RE (rejected). License Issuance (DL10) DLISISSU: issuing a license for an approved application, including validity and expiry calculation, license number generation, recording in the issued-license table and printing via DLISLPRT.
Architecture
Application Lifecycle & Status Flow End-to-end view of how a license application moves from entry through eligibility, history, payment, first and second approval to issuance, including the status codes and gating conditions between steps. Data Architecture (DB2) DB2 tables used across DLIS (CANDIDATE, LICENSE_APPLICATION, LICENSE_FEE_SCHEDULE, PAYMENT, ISSUED_LICENSE, authority user data, driving incidents) and which programs read or write them. CICS Integration Patterns Common CICS design patterns in DLIS: pseudo-conversational processing, BMS maps, COMMAREA context passing, program-to-program control transfer with XCTL and LINK, and print program delegation.
