📋 1. Change Summary

Change Specification

TitleAdd Vehicle Class Field to License Application Process
TypeEnhancement
Entry PointDLISAPPL.cbl — Transaction DL03
Requested Class ValuesA (Heavy), B (Medium), C (Light), D (Motorcycle)

Vehicle Class is currently only collected at issuance (DLISISSU / DL10). This change captures it at application entry (DLISAPPL / DL03), stores it in DLIS.LICENSE_APPLICATION, and propagates it via COMMAREA through the full review workflow — preventing late-stage class mismatches and enabling class-specific fee/approval rules.

Key Technologies Involved

IBM Enterprise COBOL CICS Transaction Server DB2 for z/OS BMS

Critical Constraint

🔴 COMMAREA Expansion Required

The 350-byte COMMAREA must expand to 352 bytes. All 10 programs hard-code LENGTH(350) in EXEC CICS RETURN — ALL must be updated atomically or Vehicle Class will be silently truncated in transit.

⚠️ 7. Risk Assessment
🔴 R1 & R2 — COMMAREA LENGTH Mismatch (CRITICAL)

IBM CICS confirms: if LENGTH in EXEC CICS RETURN is smaller than the actual COMMAREA structure, CICS silently drops the extra bytes — no LENGERR is raised. CA-VEHICLE-CLASS will be binary zeros in all downstream programs if even one program still returns with LENGTH(350). Mixed deployment of old and new load modules in the same CICS region creates the same failure. Mandatory: update all 18 occurrences atomically; deploy in a single maintenance window.

🔴 R3 — DB2 Package Timestamp Mismatch (CRITICAL)

After recompile, the DB2 precompiler generates a new DBRM timestamp. Any program executed before rebind receives SQLCODE -805 or -818 and abends. All 8 SQL programs must be rebound via DLISBIND.jcl before deployment. Mandatory: include bind step in deployment checklist and verify RC=0.

🟠 R4 — BMS Symbolic Map Out-of-Sync

If DLISAPPL.cbl is compiled before DLISAE.bms is reassembled, the DAEVCLSI field will not be resolved. Assemble BMS map first; only compile DLISAPPL after the new symbolic copybook is generated.

🟠 R5 — DB2 CHECK Constraint vs. DEFAULT Value

If the DEFAULT 'C' value does not satisfy the CHECK constraint definition, the ALTER TABLE will fail. Confirm that 'C' is in ('A','B','C','D') and test in a non-production DB2 subsystem first.

🟡 R6 — In-Flight Applications Receive Default 'C'

Existing applications not yet issued (status PE/EC/HC/PA/A2/AP) will receive VEHICLE_CLASS='C' after ALTER TABLE. Review and manually correct if the actual vehicle class is known before cutover.

🟡 R7 — CICS Mapset Cache

Old BMS mapset load module may remain cached after reassembly. Issue CEDA INSTALL MAPSET(DLISAE) explicitly and verify with CEMT INQ MAPSET(DLISAE).
