1. Program Overview

DLISISSU is a CICS pseudo-conversational COBOL online program that implements the driver license issuance function within the DLIS (Driver Licensing Information System) application suite. It runs under CICS transaction identifier DL09 and uses BMS map DLISLIM01 within mapset DLISLI as its single screen. The program has no file I/O other than its two DB2 table interactions; all persistence is managed through embedded SQL.

The program terminates every processing cycle with STOP RUN, which in a CICS environment returns control to CICS — it does not keep the task alive across terminal interactions. State is preserved across screen interactions by returning control to CICS with EXEC CICS RETURN TRANSID('DL09') COMMAREA(DLIS-COMMAREA) LENGTH(350), which re-queues the transaction and carries a 350-byte communication area into the next invocation.

Transaction: DL09 Map: DLISLIM01 Mapset: DLISLI COMMAREA: 350 bytes DB2 tables: ISSUED_LICENSE, LICENSE_APPLICATION CICS LINK: DLISLPRT

2. Data Structures and Copybooks

The WORKING-STORAGE SECTION is built from several inline-expanded copybooks (originally COPY statements that are present but commented out):

WS-COMMON-AREA (from DLISWS)

Holds the current date broken into WS-CURR-YYYY, WS-CURR-MM, and WS-CURR-DD components, a message text area (WS-RETURN-MSG), the signed return code (WS-RETURN-CODE), the current user ID (WS-USER-ID), and a message color indicator defaulting to 'GREEN'.

WS-APPLICATION (from DLISWS)

Holds the working copy of application-level status indicators used during processing: WS-APPLICATION-ID, WS-LICENSE-TYPE, WS-APP-STATUS, and the five gate statuses — WS-ELIG-STATUS, WS-HIST-STATUS, WS-PAY-STATUS, WS-APP1-STATUS, WS-APP2-STATUS.

WS-LICENSE (from DLISWS)

Contains the generated license data for a current issuance cycle: WS-LICENSE-NUMBER (20 characters), WS-VEHICLE-CLASS, WS-RESTRICTIONS, WS-ISSUED-BY-OFFICER, WS-ISSUED-BY-AUTH, WS-EXPIRY-DATE, WS-YEARS-VALID, and WS-LIC-PREFIX (3 characters). The working-storage fields WS-ISSUE-DATE, WS-EXPIRY-YYYY, and WS-EXPIRY-MMDD are declared at the 01 level separately to support date calculations.

SQLCA

The SQL Communication Area is included twice: once within the DLISWS copybook expansion and once directly at line 389. After every SQL execution, DB2 places a return code in SQLCODE. A value of 0 signals success, +100 signals no row found (NOT FOUND condition), and a negative value signals a DB2 error.

COMMAREA Layouts (from DLISCSEC)

Three COMMAREA structures are declared:

  • DLIS-COMMAREA — the primary 350-byte navigation commarea containing CA-TRANSACTION-ID, CA-CANDIDATE-ID, CA-APPLICATION-ID, CA-LICENSE-ID, CA-PAYMENT-ID, CA-USER-ID, CA-RETURN-CODE, CA-MSG-TEXT, CA-MSG-COLOR, and CA-ACTION.
  • DLIS-CAND-COMMAREA — candidate personal data layout.
  • DLIS-APPL-COMMAREA — application status data layout including all five gate statuses and CA-LICENSE-NUMBER.

All three structures share the same 350-byte DFHCOMMAREA storage in the LINKAGE SECTION through the CICS COMMAREA mechanism; the program overlays DFHCOMMAREA onto DLIS-COMMAREA by a direct MOVE at the start of subsequent invocations.

Null Indicators

WS-NULL-INDICATORS holds nine halfword COMP indicators (NI-ADDR2, NI-ELIG-DATE, NI-HIST-DATE, NI-PAY-REF, NI-A1-DATE, NI-A2-DATE, NI-SUSP-END, NI-EXPIRY, NI-PREV-LIC), all initialized to 0. These are declared but none are referenced as indicator variables in any SQL statement — they are present as part of the shared working storage copybook.

3. Pseudo-Conversational Execution Model

DLISISSU follows the standard CICS pseudo-conversational pattern. When EIBCALEN equals zero, no commarea was passed to the task, meaning this is the very first invocation — the program routes to INIT-SCREEN. On every subsequent invocation EIBCALEN is non-zero, and DFHCOMMAREA is moved into DLIS-COMMAREA before control passes to PROCESS-INPUT.

After each cycle, the program issues:

EXEC CICS RETURN TRANSID('DL09') COMMAREA(DLIS-COMMAREA) LENGTH(350)

This suspends the task, returns the terminal to the user, and pre-arms CICS to re-invoke DLISISSU under transaction DL09 the next time the user presses an attention key. This means no CICS task exists between keystrokes and no z/OS storage is held — the full 350-byte state of the conversation lives exclusively in the CICS-managed COMMAREA.

Key design point: The bare EXEC CICS RETURN END-EXEC used for the F12 exit path does not specify a TRANSID, so CICS does not pre-arm the next invocation and the transaction terminates definitively.

4. Procedure Division — Execution Flow

MAIN-LOGIC (Entry Point)

This is the sole entry point. It tests EIBCALEN:

  • = 0 → PERFORM INIT-SCREEN
  • ≠ 0 → MOVE DFHCOMMAREA TO DLIS-COMMAREA, then PERFORM PROCESS-INPUT

The paragraph ends with STOP RUN, which terminates the CICS task after the chosen path completes.

INIT-SCREEN — First Invocation Initialization

Executed only when the transaction is started fresh (no commarea). The current system date is obtained via the CURRENT-DATE intrinsic function, with the first 10 characters moved to DLIDATE (the date output field on the map). Then:

  1. EXEC CICS SEND MAP('DLISLIM01') MAPSET('DLISLI') ERASE FREEKB RESP(WS-RESP1) — sends the map to the 3270 terminal. ERASE clears the entire screen buffer and returns the cursor to the upper-left corner. FREEKB unlocks the 3270 keyboard so the operator can type immediately.
  2. EXEC CICS RETURN TRANSID('DL09') COMMAREA(DLIS-COMMAREA) LENGTH(350) — terminates the task and instructs CICS to re-invoke DLISISSU under DL09 at the next attention keystroke, setting EIBCALEN to 350 on the next invocation.

PROCESS-INPUT — Subsequent Invocation Dispatcher

Executes on every invocation after the first. It first reads the screen input:

EXEC CICS RECEIVE MAP('DLISLIM01') MAPSET('DLISLI') RESP(WS-RESP1) — maps the inbound 3270 data stream from the terminal into the symbolic map area. BMS translates each modified screen field into the corresponding -I (input) suffix map field. After this command, EIBAID contains the one-byte Attention Identifier (AID) corresponding to the key pressed.

An EVALUATE TRUE block dispatches on EIBAID:

AID ValueKeyAction
DFHPF1F1PERFORM ISSUE-LICENSE
DFHPF3F3PERFORM LOAD-APPLICATION
DFHPF6F6PERFORM PRINT-LICENSE
DFHPF12F12EXEC CICS RETURN END-EXEC — unconditional exit, no re-queue
Any otherOTHERMoves 'USE F1 F3 F6 OR F12' to DLIMSG

After the EVALUATE (for all paths except F12), control falls through to:

  1. EXEC CICS SEND MAP('DLISLIM01') MAPSET('DLISLI') DATAONLY FREEKB RESP(WS-RESP1) — sends the updated map back using DATAONLY, which writes only the application data fields without re-transmitting static screen labels, reducing network traffic.
  2. EXEC CICS RETURN TRANSID('DL09') COMMAREA(DLIS-COMMAREA) LENGTH(350) — re-queues the transaction.
Unhandled AID values: When a key other than PF1, PF3, PF6, or PF12 is pressed (e.g., Enter, PF2, Clear, PA keys), the OTHER branch sets the message field to guidance text and falls through to SEND MAP DATAONLY. No ABEND or error is raised.

5. Functional Areas

F3 — LOAD-APPLICATION Paragraph

This paragraph retrieves a license application and its associated candidate from DB2 using the Application ID entered on the screen (DLIAIDI).

Input validation: If DLIAIDI is zero, the message 'ENTER APPLICATION ID' is placed in DLIMSG and the paragraph exits via GO TO LOAD-APP-EXIT.

DB2 SELECT — JOIN query: A single SELECT … INTO retrieves eight columns from DLIS.LICENSE_APPLICATION and two from DLIS.CANDIDATE via a JOIN on CANDIDATE_ID:

  • From DLIS.LICENSE_APPLICATION: CANDIDATE_ID, LICENSE_TYPE, APPLICATION_STATUS, ELIG_CHECK_STATUS, HIST_CHECK_STATUS, PAYMENT_STATUS, APPROVAL_1_STATUS, APPROVAL_2_STATUS.
  • From DLIS.CANDIDATE: FIRST_NAME, LAST_NAME.

Result handling:

  • If SQLCODE = 100 (NOT FOUND): 'APPLICATION NOT FOUND' is moved to DLIMSG and the paragraph exits.
  • On success: the candidate's full name is assembled using a STRING statement into DLICNAMO. All five gate statuses and LICENSE-TYPE are moved to their respective map output fields. The message 'APPLICATION LOADED' is placed in DLIMSG to signal success to the caller.

F1 — ISSUE-LICENSE Paragraph

This is the primary business logic paragraph. It performs all validation, date calculation, license number generation, and database writes necessary to issue a driver license.

Step 1 — Screen Field Validation (Four Guards)

Four sequential guards validate mandatory input fields. Any failure sets a descriptive message in DLIMSG and branches to ISSUE-LIC-EXIT, bypassing all further processing:

GuardConditionMessage
Application IDDLIAIDI = ZEROS'ENTER APPLICATION ID'
Vehicle ClassDLIVCLSI = SPACES or not in ('A','B','C','D')'VEHICLE CLASS MUST BE A B C OR D'
Issuing OfficerDLIOFCRI = SPACES'ISSUING OFFICER IS REQUIRED'
Issuing AuthorityDLIAUTHI = SPACES'ISSUING AUTHORITY IS REQUIRED'

Step 2 — Application Load and Status Gate

PERFORM LOAD-APPLICATION is called inline. If DLIMSG is anything other than 'APPLICATION LOADED', the paragraph exits immediately. After a successful load, APPLICATION-STATUS is checked — if it is not 'AP' (Approved), the message 'APPLICATION STATUS MUST BE AP BEFORE ISSUE' is set and the paragraph exits.

Note: The five individual gate fields (eligibility, history, payment, approval 1, approval 2) are displayed to the user for review but are not individually re-evaluated in the issuance logic — only the composite 'AP' status is enforced programmatically.

Step 3 — Expiry Date Calculation

The current system date is obtained via CURRENT-DATE:

  • CURRENT-DATE(1:10) → WS-ISSUE-DATE
  • CURRENT-DATE(1:4) → WS-EXPIRY-YYYY
  • CURRENT-DATE(5:6) → WS-EXPIRY-MMDD

An EVALUATE on LICENSE-TYPE sets the validity period and license number prefix:

License TypeYears AddedPrefix
'L' — Learner1'LRN'
'P' — Probationary2'PRB'
'O' — Open5'OPN'
Silent boundary behavior: The EVALUATE covers only 'L', 'P', and 'O'. Any other license type value causes no WHEN branch to match — WS-LIC-PREFIX remains spaces and WS-EXPIRY-YYYY is not incremented, producing a malformed license number and a same-year expiry date with no error message or abend.

Step 4 — License Number Generation

STRING WS-LIC-PREFIX DLIVCLSI CANDIDATE-ID APPLICATION-ID INTO WS-LICENSE-NUMBER

The 20-character WS-LICENSE-NUMBER is constructed by concatenating without delimiters: the 3-character type prefix, the vehicle class, the packed-decimal CANDIDATE-ID, and the packed-decimal APPLICATION-ID.

Packed decimal in STRING: Because CANDIDATE-ID and APPLICATION-ID are PIC S9(10) COMP-3 (packed decimal), their raw internal representation is concatenated into the license number string without a prior MOVE to a display field. This means the license number may contain non-printable bytes.

  • DLIOFCRI → ISSUED-BY-OFFICER OF DCLDLIS-ISSUED-LIC
  • DLIAUTHI → ISSUED-BY-AUTH OF DCLDLIS-ISSUED-LIC
  • DLIRSTI → RESTRICTIONS OF DCLDLIS-ISSUED-LIC

Hardcoded business rules: LICENSE_STATUS is always 'A' (Active). DEMERIT_BALANCE is always initialized to 12 — every newly issued license starts with 12 demerit points regardless of license type or candidate history.

If SQLCODE NOT = 0 after the INSERT, 'DATABASE ERROR ON LICENSE INSERT' is placed in DLIMSG and the paragraph exits. No rollback is explicitly issued; CICS manages the unit of work sync point at task end via STOP RUN.

Step 6 — DB2 UPDATE of DLIS.LICENSE_APPLICATION

UPDATE DLIS.LICENSE_APPLICATION SET APPLICATION_STATUS = 'IS', LAST_UPDATED_DATE = CURRENT DATE, LAST_UPDATED_BY = :DLIOFCRI WHERE APPLICATION_ID = :APPLICATION-ID

The application record is updated to status 'IS' (Issued). LAST_UPDATED_DATE is set to the DB2 CURRENT DATE special register. LAST_UPDATED_BY is populated with the issuing officer identifier.

Unchecked SQLCODE: The SQLCODE from this UPDATE is not individually checked. If it fails silently, the license INSERT stands but the application status remains 'AP', creating a potential data inconsistency.

Step 7 — Screen Update on Success

WS-LICENSE-NUMBER is moved to DLIILNUMO (issued license number output field) and WS-EXPIRY-DATE is moved to DLIEXPO (expiry date output field). The message 'DRIVER LICENSE ISSUED SUCCESSFULLY' is placed in DLIMSG.

F6 — PRINT-LICENSE Paragraph

This paragraph delegates printing to an external program.

Guard: If DLIILNUMO is spaces, the message 'ISSUE LICENSE FIRST BEFORE PRINTING' is set and the paragraph exits. A license must have been successfully issued in a prior F1 invocation within the same session.

Program delegation: EXEC CICS LINK PROGRAM('DLISLPRT') COMMAREA(DLIS-COMMAREA) LENGTH(350) — issues a synchronous CICS LINK to DLISLPRT. DLISISSU suspends at the LINK point, DLISLPRT runs to completion, then control is returned to the statement immediately following the LINK. After the LINK returns, 'LICENSE SENT TO PRINTER' is moved to DLIMSG.

F12 — Exit

EXEC CICS RETURN END-EXEC within the EVALUATE block terminates the task definitively. Unlike the RETURN TRANSID('DL09') COMMAREA(…) form used for pseudo-conversational re-queue, this bare RETURN does not specify a TRANSID, so CICS does not pre-arm the next invocation and the transaction ends. The remaining code in PROCESS-INPUT is never reached.
